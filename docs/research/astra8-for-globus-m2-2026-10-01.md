# ASTRA 8 для «Глобус-М2»: что реально мешает и что уже работает

Дата: 2026-10-01. Код: `astra-src` `67281112` (upstream `main`); расчёты — в рабочей установке `~/astra/a8` (`e66f6ba1`, gfortran 13 + OpenBLAS).

Документ проверяет по исходникам и расчётам четыре тезиса, которые мы формулировали для лаборатории, и уточняет их. Общий контекст о токамаке, задачах лаборатории и литературе — в документации по исходникам `astra-src/docs/`, прежде всего [10 — использование на токамаке](../../astra-src/docs/10-tokamak-usage.md) (§7–9) и [07 — нагрев](../../astra-src/docs/07-heating-and-external-modules.md). Здесь — только новое и поправки.

Пометки: **проверено** — по коду с номерами строк или расчётом; **вывод** — следует из кода, но не проверено расчётом; **предположение** — по косвенным признакам.

## 1. NBI

### 1.1. Встроенный модуль работает — проверено расчётом

Модуль NBI А. Р. Полевого (`src/nbi/`, точка входа `repo_user_area/sbr/nbi.f90`) собирается всегда, как `lib/libnbi.a`, без внешних библиотек.

Расчёт: модель `equ/flux_nbi` (пример разработчиков) с закомментированным `TORBA` (ECRH, закрыт), данные `aug34954`, t = 4.0–4.5 с, batch:

```bash
cd ~/astra/a8
sed 's#^TORBA#!TORBA#' equ/flux_nbi > equ/flux_nbi_open
cp equ/log/flux_nbi equ/log/flux_nbi_open        # каждой модели нужен equ/log/<модель>
astra8 -m flux_nbi_open -v aug34954 -s 4 -e 4.5 -batch
```

Результат: `ASTRA normal exit`, 19 с. Сравнение с эталоном разработчиков `regressions/aug34954flux_nbi.CDF` (Intel + MKL, с TORBEAM) на t = 4.4 с:

| величина | наш расчёт (центр) | эталон | расхождение |
|---|---|---|---|
| `PIBM`, нагрев ионов пучком, МВт/м³ | 0.563 | 0.566 | ~0.5 % |
| `PEBM`, нагрев электронов пучком, МВт/м³ | 0.1138 | 0.1141 | ~0.3 % |

`T_e`, `T_i`, `n_e` в этой модели заданы из эксперимента (`TE=TEX` и т. д.), поэтому отключение ECRH на отложение пучка почти не влияет, и сравнение корректно.

Попутно: модель без файла `equ/log/<модель>` падает с `Error: file "equ/log/<модель>" missing`. Это надо помнить при создании своих моделей копированием.

### 1.2. Какие потери учитывает встроенный модуль — проверено по коду

| канал потерь (по слайдам STW-2022 для #41585) | на «Глобус-М2» | во встроенном NBI |
|---|---|---|
| перезарядка (CX) | 200 кВт | есть: `CNB2=1` (CX на ионах плазмы), `CNBI1`/`CNBI3` (CX быстрых ионов на холодных нейтралах и нейтралах пучка, при `CNB4=2`); выход `PBCX`, `SBICX` — добавлены в августе 2026 (`src/nbi/nbibce.f90:254`, `656`) |
| «плохие» орбиты (первая орбита) | 50 кВт | есть: `NBORBCO`, «First orbit analysis … guide centre apprx.» (`src/nbi/nbicom.f90:1298`), вызывается для пролётных и запертых частиц (`nbicom.f90:1182`, `1193`): частица либо теряется (`JLOSS=1`), либо её вклад размазывается по ширине орбиты |
| прострел (shine-through) | 10 кВт | есть: `p_shine` (`src/nbi/nbicom.f90:410–516`) |
| гофрировка поля (ripple) | — | есть, по умолчанию выключена (`nb_injection.f90:529–537`) |

Модуль активно правится: в 2026 году переписан (март), в мае исправлен нестационарный Фоккер–Планк (`CNB4=2`), в августе добавлены правки «according to Polevoi».

Чем он проще NUBEAM (**вывод**): это детерминированная модель «карандашных» пучков с ведущим центром, а не Монте-Карло с полными орбитами. Нет 3D-геометрии потерь и взаимодействия с вращением, которое лаборатория учитывала в связке ASTRA + NUBEAM ([Zenkova 2024], `astra-src/docs/10-tokamak-usage.md` §7.2). Подходит ли он для их задач, решает лаборатория. Но как стартовую точку, без закрытых кодов, его можно использовать уже сейчас.

### 1.3. Что нужно для «Глобус-М2»

- Файл геометрии инжекторов `exp/nbi/<имя эксперимента>` или `exp/nbi/<машина>`: по 4 строки на источник (поля по 12 символов, `docu/section4.tex`, табл. 4.31; разбор — `astra-src/docs/07` §5). Пример — `exp/nbi/aug34954`, 8 источников AUG. Для «Глобус-М2» — 2 инжектора: нужны геометрия пучков, энергия (18–50 кэВ), сорт частиц (H/D), доли энергетических компонент.
- Мощность по источникам — через `ZRD1..ZRDn` в файле эксперимента (в `aug34954` заданы `ZRD3`, `ZRD8` по 2.5 МВт).
- Параметры `CNB1..CNB4` в модели: число источников, CX, сетка, решатель Фоккера–Планка.

### 1.4. NUBEAM

Слова `nubeam` нет ни в одном файле исходников ASTRA 8 и ни в одном коммите всей истории оригинала (`git log --all -i -S nubeam` — пусто). NUBEAM не входит и в ASTRA 7: в работах лаборатории связка ASTRA + NUBEAM — отдельная программа на Python ([Zenkova 2024], [Petrov 2022]). Модель лаборатории `NBI_nubeam_Int_CXRS.model` (**предположение**) получает профили пучка из NUBEAM извне. В A8 такие профили подаются через `PEX`/`PIX`/`CUX`/`SNX` или `CARnX` из U-файлов (`astra-src/docs/07` §11). Программу-связку лаборатории придётся переносить вместе с моделью.

## 2. Равновесие и геометрия «Глобус-М2»

Проверено по коду (`src/astra/metrics.f90`, `stepup.F90`, `gs_solver.F90`, `machine_config.f90`, `src/feqis/`, `exe/greenMatrices.py`) и синтетическим расчётом.

### 2.1. Варианты равновесия

Решатель выбирает `IPEQL` в модели (`metrics.f90:118–213`, по умолчанию 5):

| `IPEQL` | решатель | для «Глобус-М2» |
|---|---|---|
| −2 | цилиндрическое аналитическое | нет |
| 0 | аналитическое начальное приближение `EQGUESS` (разложение по `a/R`) | нет |
| 1 | EMEQ, трёхмоментный | **вывод:** моментный метод, при `A≈1.5` может быть неточен |
| −1, −6 | метрика целиком из эксперимента (профили `SHX`, `ELX`, `G11X`, ... или `input_metric.dat`) | возможно, если метрику даёт внешний код равновесия |
| 4 | SPIDER, только заданная граница (свободная граница SPIDER удалена в A8) | закрыт, недоступен |
| **5** | **FEQIS**, заданная или свободная граница | **основной путь** |

**Заданная граница или свободная — решает не `IPEQL`, а `ITFBE`** (`stepup.F90:49–56`): по умолчанию `1e6`, то есть всегда заданная граница; `ITFBE>0` — свободная граница с момента `TIME ≥ ITFBE`. Свободную границу из примеров включает только `equ/fbe` (`ITFBE=2.5; ICIRCQ=1`).

### 2.2. Заданная граница: геометрия машины не нужна

Граница подаётся из файла эксперимента:

- `NAMEXP BND POINTS n NTIMES m` прямо в файле: времена, затем для каждой точки `R` и `Z` (`read_input.f90:758–833`);
- `NAMEXP BNDU` и путь на следующей строке → пара 2D U-файлов `udb/<путь>_r`, `udb/<путь>_z` (время × номер точки, метры). Так сделан тест `aug34954`: `udb/34954/34954.bnd.txt_r/_z`, 10 времён × 180 точек.

Между срезами граница интерполируется линейно, за краями — постоянна (`metrics.f90:1319+`). Перед решением контур аппроксимируется 7 гармониками Фурье (`gs_solver.F90:243`), поэтому углы X-точки сглаживаются. Точек на срез — меньше 1000 (локальные массивы в `metrics.f90:1127`).

**EFIT.** Читателя g-файлов (EQDSK) для равновесия ASTRA нет: `sbr/a2eqdsk.f90` только **пишет** EQDSK, `python/eqdsk_to_TORIC_gs.py` читает его для TORIC. Чтобы брать границу из EFIT, нужен небольшой новый скрипт: последняя замкнутая поверхность (или поверхность ~99.5 % потока) по срезам → пара U-файлов `BNDU` или блок `BND` (**вывод**, скрипта нет).

### 2.3. Проверка на «Глобус-подобной» геометрии — синтетический расчёт

Готового описания сферического токамака нет нигде: ни в коде, ни в конфигурациях, ни в истории git оригинала (1806 коммитов; поиск globus, NSTX, ST40, spherical). Поэтому проверили сами, **на синтетических данных** (это не разряд «Глобус-М2», профили условные):

- `R=0.36` м, `a=0.24` м, `κ=1.9`, `δ=0.3` (аспектное отношение 1.5), `I_p=0.3` МА, `B_T=0.8` Тл, `NA1=51`;
- граница — блок `BND`, 64 точки, форма `R=R₀+a·cos(θ+δ·sinθ)`, `Z=κ·a·sinθ`;
- профили `T_e`, `T_i`, `n_e`, `q` — параболы на 11 точках (`GRIDTYPE 12`);
- модель `equ/flux_feqis` (FEQIS, `IPEQL=5`, заданная граница), машина `-dev gm2` без JSON-описания;
- файл: `~/astra/a8/exp/gm2synth` (генератор — в приложении).

```bash
astra8 -m flux_feqis -v gm2synth -s 0.1 -e 0.5 -dev gm2 -batch
```

Результат: `ASTRA normal exit`, 9 шагов, 12 с, NaN нет.

| величина | задано | t=0.1 | t=0.3 | t=0.5 |
|---|---|---|---|---|
| вытянутость на границе `ELONG` | 1.9 | 1.899 | 1.899 | 1.899 |
| треугольность `TRIAN` | 0.3 | 0.288 | 0.289 | 0.288 |
| шафрановский сдвиг оси, м | — | 0.058 | 0.046 | 0.046 |
| `li3` | — | 0.34 | 0.75 | 0.67 |

Форма воспроизводится (треугольность чуть меньше из-за Фурье-аппроксимации), решение устойчиво во времени. Профиль `q` при этом эволюционирует как попало (`q₀` падает ниже 1): в модели нет пилообразных колебаний, профили условные. **Вывод:** численно FEQIS с заданной границей при `A≈1.5` работает. Физическую правильность это не подтверждает: нужна сверка с EFIT на реальном разряде.

Попутно найдено:

- В файле эксперимента нужно явно задать `ABC` (малый радиус плазмы): по умолчанию `ABC=0.3` м (`scalars.f90:167`), что больше малого радиуса «Глобуса», и расчёт останавливается с `ABC cannot exceed AB` (`set_x_data.f90:533`).
- `AB`, `AWALL` — размеры камеры, они должны быть не меньше границы плазмы.
- Без `-dev` берётся `aug`: сетка AUG `R=1.0–2.3` м из `exp/cnf/aug_description_in.json`, и граница «Глобуса» в неё не попадает (**вывод** по `gs_solver.F90:250–262`). Если файла описания нет, сетка 65×65 строится вокруг границы ±5 см — это и сработало с `-dev gm2`.
- Имя машины — **не длиннее 4 символов и без `_`**: в Фортране `machine` — `character(len=4)` (`read_input.f90:11`). С `-dev globus` Фортран будет искать `glob_description_*.json`, а `greenMatrices.py` напишет `globus_description_full.json`. Подходят `gm2`, `glob`.

### 2.4. Свободная граница: нужен файл описания машины (данные, не код)

Для свободной границы FEQIS берёт геометрию из `exp/cnf/<машина>_description_in.json` (`machine_config.f90:18`). `exe/greenMatrices.py` при каждом запуске пересчитывает из него `<машина>_description_full.json`: индуктивности катушек, функции Грина на сетке и для границы, производные для сил, маску лимитера, сопротивления пассивных проводников (`feqis_solvers.f90:561`).

Ключи JSON (по примеру AUG — единственному полному; файлы ITER и JET содержат только графику и для FEQIS не годятся):

| ключ | смысл |
|---|---|
| `nR, nZ, Rmin, Rmax, Zmin, Zmax` | расчётная сетка, м; используется и для заданной границы, если файл есть |
| `alpsep` | уровень нормированного потока, принимаемый за границу (0.995) |
| `R_coil, Z_coil, dR_coil, dZ_coil, ang_coil, angh_coil` | блоки катушек: центр, размеры, углы параллелограмма |
| `m_turns`, `n_elem_coil` | витки и число нитей в блоке |
| `m_equiv` | номер цепи (эквивалентной катушки) для каждого блока; максимум = число активных цепей = число токов `CCOIL` в файле эксперимента (12 для AUG) |
| `resConduc` | матрица сопротивлений цепей (единицы в коде не указаны — сверять с AUG) |
| `Rlim, Zlim`, `lim_max/minR/Z` | лимитер и допустимая область плазмы |
| `x1..x4`, `res_blan`, `width_blan` | пассивная стенка отрезками и её сопротивление |
| `Rvessel, Zvessel, contour_*` | только для графики |

Кроме JSON для свободной границы нужны:

- токи катушек `NAMEXP CCOIL` (кА) по времени в файле эксперимента (`read_input.f90:745–756`). До `ITFBE` они берутся как есть, после — из уравнений цепей (`stepup.F90:79–85`);
- пользовательская подпрограмма в `sbr/`, задающая параметры `transport2fbe` (`cur_init`, `current_limit_feqis`, `sigma_*`, `refit_mode`, ...; `addendum_A8.tex:616–654`). Без неё, по документации, расчёт падает; эталонный `eqctst.f90` в репозитории отсутствует.

Жёстко зашитых констант AUG и проверок аспектного отношения в `src/feqis` и `src/astra` не найдено. Ограничения массивов: до 300 блоков катушек, 251 точка по `ρ` в 2D, 500 кандидатов в X-точки. Функции Грина (эллиптические интегралы) требуют `R>0`: `Rmin` сетки — выше ~0.05 м с учётом центрального столба.

Итого: тезис «придётся писать код» верен **только для свободной границы**, и то в основном это данные (JSON с катушками и камерой, токи катушек) плюс одна настроечная подпрограмма. Для заданной границы достаточно контура из EFIT.

Документация разработчиков здесь устарела: `addendum_A8.tex:606` и руководство FEQIS упоминают `machine_description_out.(dev)` и `exp/equ/<machine>/coil.dat`, а код работает с JSON.

## 3. Перенос моделей и данных из ASTRA 7

Проверено по коду и прогоном парсера (подробности со строками — ниже).

### 3.1. Конвертера и режима совместимости нет

Поиск `A7`, `astra7`, `legacy`, `old format`, `convert`, `compat` по `pyparse/`, `exe/`, `preProcess/`, `docu/` ничего относящегося к делу не находит.

### 3.2. Данные эксперимента (`exp/`): два читателя, ломается один

Файл эксперимента читают **дважды**:

1. **Python-парсер** `pyparse/exp_parser.py` — при сборке (`exe/Makefile:173`). Он генерирует код и вычисляет размер массивов (`nr_x_max`, `src/astra/read_input.f90:62`).
2. **Фортрановский читатель** `read_exp` (`src/astra/read_input.f90:208–993`) — при запуске расчёта. Он сохранил поведение A7: свободный формат `NAMEXP` для скаляров (стр. 285), ключ `PROFIL` (стр. 282), неявную равномерную сетку при `GRIDTYPE<10` (`set_x_data.f90:190–193`), один скаляр `r0/z0` для `GRIDTYPE 18/19` (`set_x_data.f90:195–198`).

Ломается первый. Почему `exp/readme` (файл эпохи A7 из самого репозитория) не проходит:

| место в `readme` | формат A7 | что ждёт Python-парсер A8 |
|---|---|---|
| стр. 36: `POINTS 21 GRIDTYPE 1 NAMEXP NE NTIMES 1` | 1 время + 21 значение; при `GRIDTYPE<10` сетка неявная, в файле её нет (`docu/section5.tex:2612–2647`) | время + **явная** сетка + значения: `1 + 21 + 21 = 43` числа → `AssertionError` (`exp_parser.py:272`) |
| `GRIDTYPE 18/19` (стр. 46–68, 121–175) | один скаляр `r0` или `z0` + `POINTS` значений сетки | `2*POINTS` значений сетки |
| `POINTS 20` и строки `TEX 0.00 ...` фиксированного формата (стр. 22–29, 212) | профиль построчно | молча игнорируется |
| разделители `****`, текст внутри данных | комментарии | удаляются только строки с `!` (`exp_parser.py:118`); текст обрывает поток чисел без ошибки (`np.fromstring`, стр. 80) |
| `TEX<tab>U-file: f  factor: 1.` | табуляции, `factor:` | `NAME U-file:путь: множитель`; исправлено нашим патчем установщика |

Следствия:

- **Тихие ошибки опаснее явных**: блок, обрезанный текстом, или проигнорированный старый профиль не дают ошибки. Расчёт пойдёт с неполными данными.
- **Вывод:** если Python недосчитает размер блока, `nr_x_max` может оказаться меньше, чем потом прочитает Фортран.
- **Путь починки** (предложение): научить Python-парсер тем же правилам, что у Фортрана (неявная сетка `GRIDTYPE<10`, `18/19` со скаляром, `*`-комментарии). Это ограниченный патч в одном файле, хороший кандидат на предложение разработчикам (Tardini). Альтернатива — конвертер файлов A7 → A8.

### 3.3. Модели (`equ/`)

Изменения языка по `docu/addendum_A8.tex:576–600` и коду `pyparse/`:

| A7 | A8 |
|---|---|
| блочные комментарии `%...%` | `/* ... */`; `%` не обрабатывается, хотя docstring `equ_prepare` обещает обратное (`parse_as.py:118–153`): **код** внутри `%`-блока становится активным, обычный текст (**вывод**) скорее даст ошибку разбора |
| выбор блока `#1 ... #` | не реализован |
| `INCLUDE` / `-i` | не реализован |
| функции `fnc` как функции от `ρ` | только как массивы (`CARxx = QETOT`) или граничные значения (`QETOTB`) |
| значение массива в точке | только через `AFX`: `TE(AFX(0.5))` |
| `fml` и `GRAD` в одной строке | нельзя |
| решатели равновесия по ключевым словам (`E3M`, `ESP`, ...) | игнорируются, решает `IPEQL` в модели (`equ_parser.py:182–185`) |
| `IPEQL` для SPIDER (свободная граница) | «SPIDER free boundary is not available anymore» (`addendum_A8.tex:589–600`) |
| запуск `astra <эксп> <модель>` | `as_exe -m <модель> -v <эксп>`, без позиционных аргументов (`exe/as_exe.py:45–65`) |
| — | для каждой модели нужен `equ/log/<модель>` |

Расширения `.model`/`.data` не обязательны и не добавляются: имя передаётся как есть (**вывод**: работать будет, если передать полное имя).

Самая опасная из этих разниц — `%`-комментарии: закомментированный в A7 **код** молча становится активным в A8 (проверено по `equ_prepare`, прогоном не проверялось).

### 3.4. U-файлы

`pyparse/ufiles.py` читает **и пишет** U-файлы (`UFILE.read`, стр. 70; `UFILE.write`, стр. 195), 1D/2D/3D, оба вида заголовков. Для профилей метка оси Y должна сводиться к `MINORRAD`, `MAJORRAD`, `RHO`, `RHO_TOR` или `POLOIDALFLUX` (`grid_d`, стр. 21). Граница — пара `<путь>_r`/`<путь>_z`. Это пригодится для экспорта из архива (§4).

Выводы:

- Из MDSplus сейчас можно сделать только **временные ряды-скаляры**: `IPL`, `BTOR`, плотность. Этого мало для расчёта.
- Для профилей нужен импорт Томсона (`TS_RESULTS` или API лаборатории), для границы — EFIT. Граница ASTRA (`BNDU`) — это контур по времени; его можно получить из A-файлов EFIT, если в них есть контур, или из g-файлов (EQDSK). Есть ли g-файлы — вопрос к лаборатории.
- Чтение сигнала по имени из MDSplus пока требует перебора узлов `:NAME`/`:ORIG_NAME` (пути — по номерам слотов `SIG_0001`), см. `tokomak/docs/runbooks/mdsip-read-contract.md`.

Цепочка «разряд → U-файлы → расчёт → результат в `.PROCESSED`» описана как предложение в `astra-src/docs/10-tokamak-usage.md` §9.

## 5. Поправки к ранее сформулированному

1. «Для NBI нужен доступ к RABBIT через IPP» → не обязательно: встроенный NBI работает и учитывает основные каналы потерь. RABBIT нужен, только если лаборатория хочет именно его.
2. «Встроенный модуль NBI или NUBEAM» → NUBEAM не путь внутри ASTRA, а внешний код; путь внутри ASTRA — встроенный NBI или профили извне через `PEX`/`PIX`.
3. «FEQIS не знает геометрию, придётся писать код» → для заданной границы (из EFIT) не нужно ничего, проверено на синтетике; для свободной — JSON с данными машины + токи катушек + настроечная подпрограмма; см. §2.
4. «Формат изменился» → изменился в Python-парсере сборки; рантайм A7 понимает. Модели требуют ручной правки по списку §3.3; главный риск — `%`-комментарии.
5. В `astra-src/docs/10-tokamak-usage.md` §8.3 пригодность встроенного NBI для «Глобус-М2» подана как полностью открытый вопрос, а в `07` нет учёта первой орбиты. Уточнение — §1.2 этого документа.

## Приложение. Генератор синтетического файла `gm2synth`

Синтетика для проверки численной работы FEQIS на сферической геометрии, не разряд. Запускать из `~/astra/a8`. Проверено: код из этого приложения даёт тот же файл, на котором шёл расчёт §2.3.

```python
import numpy as np
R0, a, kap, dlt = 0.36, 0.24, 1.9, 0.3
lines = ["Globus-M2-like SYNTHETIC test (not a real shot)",
         " Name ||Time  || Value|| Error", "______||______||______||______"]
for n, v in [("NA1", 51), ("RTOR", 0.36), ("AWALL", 0.32), ("ELONM", 1.9), ("TRICH", 0.3),
             ("AB", 0.30), ("ABC", 0.24), ("ZMJ", 1.0), ("AMJ", 2.0), ("IPL", 0.30), ("BTOR", 0.80)]:
    lines.append(f"{n:<16}{v}")                     # скаляры: имя в колонках 0-5, значение с 16-й
lines.append("")
rho = np.linspace(0, 1, 11)
prof = {"TE": 0.05 + 0.9*(1 - rho**2)**1.5, "TI": 0.05 + 0.6*(1 - rho**2)**1.5,
        "NE": 1.0 + 4.0*(1 - rho**2)**0.7, "VTOR": 0*rho, "CAR2": 1.0 + 3.5*rho**2}
fmt = lambda arr: "\n".join("  " + "  ".join(f"{x:.4f}" for x in arr[i:i+6]) for i in range(0, len(arr), 6))
for k, v in prof.items():                           # время, явная сетка, значения
    lines += [f"NAMEXP {k} POINTS {len(rho)} GRIDTYPE 12 NTIMES 1", " 0.0000", fmt(rho), fmt(v), ""]
th = np.linspace(0, 2*np.pi, 65)[:-1]
Rb, Zb = R0 + a*np.cos(th + dlt*np.sin(th)), kap*a*np.sin(th)
lines += [f"NAMEXP BND POINTS {len(th)} NTIMES 1", " 0.0000", fmt(np.ravel(np.column_stack([Rb, Zb]))), ""]
open("exp/gm2synth", "w").write("\n".join(lines) + "\n")
```
