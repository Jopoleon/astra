## 1. Кто и когда читает данные

Файл эксперимента читают два независимых парсера:

| этап | код | что делает | ошибки |
|---|---|---|---|
| сборка | `pyparse/exp_parser.py` (`EXP_PARSER`), вызывается из `pyparse/parser_main.py` | предупреждает о `X`-массивах модели, которых нет в эксперименте; считает `nr_x_max` = максимум длины радиальной сетки | падение останавливает генерацию `src/tmp` |
| счёт | `src/astra/read_input.f90::read_exp` | читает **реальные** данные: скаляры, профили, границу, катушки, U-файлы | `ERROR STOP`, предупреждения в stdout, иногда тихий пропуск строк |

Правила разбора у двух парсеров **разные** (§9, §13). Если Python-парсер принял файл, это ещё не значит, что Fortran прочтёт данные, и наоборот. Файл эксперимента не входит в зависимости `make` (`repo_user_area/exe/Makefile`): после его изменения без изменения модели `src/tmp` не пересобирается ([03-model-language.md](03-model-language.md), §1).

Имя файла передаётся опцией `-v` (`repo_user_area/exe/as_exe.py`) и попадает в `tmp/astra.nml` как `exp_file`. Fortran открывает `exp/<exp_file>` (`read_input.f90::readInput`, строки 47–114).

## 2. Общая структура файла эксперимента

```text
<строка заголовка 1>                      ← читается '(A132/)': первая строка + пропуск второй
<строка заголовка 2>
<скалярная секция>                        ← до первой строки, содержащей слово POINTS/GRIDTY/FILTER/PROFIL
<секция профилей>                         ← группы NAMEXP …, строки U-file, BND/CCOIL/VCOIL
END                                       ← необязательно
```

Источники: `read_input.f90::read_exp`. Первый проход, подсчёт размеров, — строки 257–410. Второй проход, скаляры, — строки 440–626. Третий проход, профили, — строки 632–992.

Общие правила Fortran-парсера:

- Строка читается форматом `(A132)`: всё после 132-го символа теряется.
- Строка, начинающаяся с `!`, — комментарий в скалярной секции (строка 463).
- `END` в начале строки завершает чтение (строки 464, 835).
- Имя величины — первые 6 символов строки (`VARNAM`). Если первый символ пробел или табуляция, строка считается комментарием. Табуляция внутри имени даёт пустое имя и флаг `ier_tab` (§9). Конечная `X` отбрасывается: `TE` и `TEX` — синонимы.
- Строки разбиваются на слова функцией `parse_utils.f90::split2array2` (строки 126–174), не больше 20 слов (`nwords_max=20`). **Строка из 21 слова и более роняет `read_exp` с SIGSEGV** (проверено, §13).

## 3. Скалярная секция

### 3.1. Фиксированный формат (как в A7)

| колонки | поле |
|---|---|
| 1–6 | имя (`variables` из `astra_variables.json`, а также `NA1`, `TSTART`, `TEND`) |
| 9–14 | время, с (пусто → 0) |
| 17–22 | значение |
| 25–30 | ошибка |
| 31– | свободный текст |

Источник: `read_input.f90`, строки 516–519; Python — `exp_parser.py::parse_exp1d`, строки 130–157.

Правила:

- Поле значения занимает **6 символов**. `1.65` помещается, `-1.234e-3` уже нет. Длинные числа задают свободным форматом (§3.2) или U-файлом.
- Несколько строк одной величины подряд задают зависимость от времени (`IFDFVX=1`, строка 585). Между точками значение интерполируется линейно, за краями экстраполируется константой (`set_x_data.f90::set_x_scalars`, строки 432–485).
- `NA1`, `TSTART`, `TEND` не могут зависеть от времени, табуляция в их строках запрещена (строки 523–541). Python-парсер дополнительно запрещает зависимость от времени для `RTOR AWALL AB ELONM TRICH AMJ ZMJ` (`exp_parser.py`, строки 137–140; там `sys.exit(1)`).
- Табуляция в строке фиксированного формата даёт `ERROR STOP … tabulation not allowed` (строки 560–564).
- Имя, которого нет среди `variables`, **молча пропускается** (строка 547). Опечатка в имени не вызывает ошибки.
- `TSTART`/`TEND` из файла перекрываются опциями `-s`/`-e` командной строки (`read_nml`, строки 137–139).

### 3.2. Свободный формат `NAMEXP` для скаляров

```text
NAMEXP IPL NTIMES 3
0.0 0.1 0.2
0.10 0.25 0.30
```

Четвёртое слово строки считается числом времён (`VTIM = strarray(4)`, строка 480). Следующая строка содержит времена, ещё одна — значения, обе читаются list-directed (строки 493–503). Если `NTIMES ≤ 1`, величина считается постоянной. Python-парсер считает `NAMEXP` началом секции профилей (`exp_parser.py`, строка 20, `delimiters`), поэтому такие скаляры при сборке не видны, но и не мешают (по коду).

### 3.3. U-файл для скаляра

```text
IPL      U-file:34954/MAG34954.IPL_AVG
BTOR     U-file:34954/MAG34954.BTOR_AVG: 1.0
```

Строка с `:` в скалярной секции считается ссылкой на U-файл (строки 555, 593–620). Разбор (`parse_u_line`, строки 1179–1223):

- имя — до первого пробела;
- остаток режется по `:`, первое поле должно быть `U-FILE` (без учёта регистра);
- второе поле — путь относительно `udb/`;
- необязательное третье поле — множитель.

Повторное определение (`IPL` из U-файла и ASCII) даёт `ERROR STOP … ambiguous … definition` (строки 550–553, 595–598). Если в U-файле одна точка по времени, величина постоянна.

### 3.4. Конец скалярной секции

Скалярная секция заканчивается на **первой строке, содержащей слово** `POINTS`, `GRIDTY…`, `FILTER` или `PROFIL…` (строки 472–476). У Python-парсера список шире: `POINTS GRIDTYPE NTIMES FILTER FACTOR NAMEXP PROFILE END` (`exp_parser.py::exp_split`).

Следствие (по коду): если профили заданы только строками U-файлов, а ни одного из этих слов в файле нет, Fortran прочтёт профили как скаляры. Имена `TE`, `NE` не найдутся среди `variables`, и **профили будут молча проигнорированы**. В `aug34954` разделителем служит строка `FILTER   0.002`; в `AUG33040_2500` — `NAMEXP CCOIL NTIMES 1 POINTS 12`. Для явного разделителя достаточно строки `PROFILES`.

## 4. Секция профилей (2D)

### 4.1. Управляющая строка

```text
NAMEXP <имя> POINTS <n> GRIDTYPE <g> [NTIMES <nt>] [FILTER <f>] [FACTOR <k>]
<nt времён>            ← только если NTIMES > 0
[<r0 или z0>]          ← только GRIDTYPE 18/19
<сетка>                ← нет при GRIDTYPE < 10; n чисел при 10–19; 2n при 20
<n значений> × max(nt,1)
```

Ключевые слова идут парами «слово значение» в любом порядке (`read_input.f90`, строки 673–720; `do j=1,n_words,2`). Сравниваются первые 6 символов, поэтому `GRIDTYPE` = `GRIDTY`. Неизвестное слово даёт сообщение `read_exp error unknown key word in string` без остановки счёта. Это безвредно, например, для строк-комментариев `*****`.

Чтение данных (строки 910–980):

- времена, сетка и значения читаются list-directed (свободный формат, переносы строк не важны);
- каждая серия читается отдельным `read`, то есть начинается с новой строки;
- серий сетки `jtype = 1 + GRIDTYPE/10` (строка 917): 1 при `GRIDTYPE<10` (только значения), 2 при 10–19 (сетка + значения), 3 при 20 (`r`, `z`, значения);
- `FACTOR` умножает значения, но не сетку;
- `POINTS ≤ 1` даёт `ERROR STOP … Number of grid points must be > 1`;
- `GRIDTYPE` вне 0–20 даёт `ERROR STOP` (строки 921–924).

**Управляющие слова не наследуются.** В начале каждой управляющей строки сбрасываются `INTYPE=-1`, `ntim=0`, `nr_exp=0`, `factor=1`, `ALFA=ALFA_GLOB` (строки 653–658). В A7 (`exp/readme`, раздел «Main Rules») `POINTS` и прочие могли переходить на следующие группы.

**`FILTER`** — параметр сглаживания `SMOOTH`, по умолчанию 0.001 (`ALFA_GLOB`, строка 638). Строка, **начинающаяся** с `FILTER`, задаёт глобальное значение для последующих групп (строка 660). `FILTER` внутри управляющей строки действует только на эту группу.

### 4.2. Строка U-файла для профиля

```text
TE       U-file:34954/E34954.IDA_AVG:    1.e-3
```

Строка разбирается так же, как в скалярной секции. Тип сетки определяется по метке второй независимой переменной (`CHECKU`, строки 1088–1176):

| начало метки (верхний регистр, табуляции → пробелы) | `GRIDTYPE` |
|---|---|
| `MINORRAD` | 10 (единица должна начинаться с `M` в колонках 21–31, иначе предупреждение) |
| `MAJORRAD` | 19 |
| `RHO` (`rho_tor` …) | 12 |
| `POLOIDALFLUX` | 13 |
| иначе | `Unrecognized "radial" variable. Input ignored.` |

Пробелы внутри метки не удаляются, поэтому «`Minor Radius`» из старого текста `exp/readme` **не** распознаётся. Писать нужно `MinorRad`. Python-парсер ещё строже: метка целиком (`uf.Y['label'].strip().upper()`) должна совпасть с ключом `MINORRAD`, `MAJORRAD`, `RHO`, `RHO_TOR`, `POLOIDALFLUX` (`exp_parser.py`, строки 21, 205). Иначе он падает с `KeyError`.

Множитель (`: 1.e-3`) переводит единицы U-файла в единицы ASTRA. Единицы в метках U-файла **не проверяются** (§7.3).

### 4.3. Несколько групп одной величины

По коду при чтении ASCII-группы `jbeg_arrx(jexar) = NGR` выставляется в начале **каждой** группы (строка 940). Для U-файла он выставляется только при смене имени (строки 735–737). `set_x_arrays` определяет диапазон времён величины через `jbeg_arrx` следующей величины (`set_x_data.f90`, строки 103–132). Если одна величина задана несколькими ASCII-группами, диапазон предыдущей величины, вероятно, захватывает чужие времена. Отсюда наблюдавшаяся ошибка `Quantity NEX Input times not ascending` на очищенном `readme`. Это гипотеза, подробно не проверено. Все рабочие примеры (`30000_3.4`, `steltest`, `aug34954`) задают каждую величину **одной** группой с нужным `NTIMES`. Так и следует делать.

Внутри группы времена должны строго возрастать: при нарушении `ERROR STOP … not ascending` / `… repeated` (`set_x_data.f90`, строки 122–130).

## 5. Типы радиальной сетки `GRIDTYPE`

Отображение на сетку ASTRA выполняет `set_x_data.f90::set_x_arrays`, строки 190–370:

| `GRIDTYPE` | координата | сетка в файле | реализация |
|---|---|---|---|
| 0 | `a/AB` | равномерная на [0,1], не задаётся | `CASE(0)` |
| 1 | `a/ABC` | равномерная | `CASE(1)` |
| 2 | `ρ/ρ_max` (тороидальный) | равномерная | `CASE(2)` |
| 3 | `ρ_pol` | равномерная | `CASE(3)` |
| 4–6 | — | — | `ERROR STOP … not implemented` |
| 10 | `a`, м (до `AB`) | задаётся | `CASE(10)` |
| 11 | `a`, м (до `ABC`) | задаётся | `CASE(11)` |
| 12 | `ρ_tor`, нормированный | задаётся | `CASE(12)`, с перенормировкой `XA/XA(NP1)` |
| 13 | `ρ_pol`, нормированный | задаётся | `CASE(13)` |
| 14 | `sqrt(V/V_tot)` | задаётся | `CASE(14)` |
| 15 | нормированный полоидальный поток | задаётся | `CASE(15)`. В формуле стоит `FP(j3)` с «висячим» индексом цикла; вероятно, опечатка вместо `FP(1)` (по коду) |
| 16 | тороидальный поток `Φ`, В·с | задаётся | `CASE(16)`: `ρ = sqrt(Φ/(π B_tor))` |
| 17 | — | — | `ERROR STOP` |
| 18 | хорда при фиксированном `r0`: точки `z_j` | `r0`, затем `z_j` | `CASE(18)`, `RZ2A` |
| 19 | хорда при фиксированном `z0`: точки `r_j` | `z0`, затем `r_j` | `CASE(19)` |
| 20 | произвольные точки `(r_j, z_j)` | `r_j`, затем `z_j` | `CASE(20)` |
| >20 | — | — | молча пропускается (`CYCLE var_loop`) |

После отображения данные сглаживаются (`SMOOTH`, строка 383) с параметром `FILTER` группы и интерполируются линейно по времени между соседними срезами (строки 409–420). До первого и после последнего среза значение постоянно.

Для `GRIDTYPE 10–16`, если последняя точка сетки не доходит до границы (с допуском `0.5/n`), добавляется точка на границе со значением последней точки (строки 236–244 и аналоги). При малом шаге у оси первая точка сдвигается в 0 (строки 377–379).

## 6. Граница плазмы и токи катушек

| блок | формат | код |
|---|---|---|
| `NAMEXP BND POINTS n NTIMES nt` | `nt` времён, затем для каждой точки контура `R(t1..tnt)` и `Z(t1..tnt)` | `read_input.f90`, строки 758–806; Python — `exp_parser.py`, строки 248–257 (`reshape(nthe, 2, nt)`) |
| `NAMEXP BNDU` + следующая строка `<путь>` | два 2D U-файла `udb/<путь>_r` и `udb/<путь>_z` (время × угол) | строки 809–834 |
| `NAMEXP CCOIL NTIMES nt POINTS ncoil` | `nt` времён, затем `ncoil × nt` токов | `read_coilx`, строки 155–206 |
| `NAMEXP VCOIL …` | то же для напряжений | там же |

Граница задаётся одной группой, иначе `ERROR STOP … Boundary must be defined in a single group`. Лимиты: `nbnd_max=400000` (точки × времена), `nt_coils_max=25000` (`ncoil × nt`). Если задана граница, `astra_assignments` вычисляет из неё `ABC` (полуширина по `R`) и `ELONG` на момент `TSTART` (`set_x_data.f90`, строки 542–562). `TRIAN` и `SHIFT` из границы **не** вычисляются. Использование границы и катушек решателями равновесия описано в [06-equilibrium.md](06-equilibrium.md).

## 7. U-файлы

### 7.1. Формат (как его читает Fortran)

Пример `udb/34954/N34954.IDA_AVG`:

```text
  34954AUGD 2 0 6              ;-SHOT #- F(X) DATA -UF2DWR- 18Jun2019
                               ;-SHOT DATE-  UFILES ASCII FILE SYSTEM
   0                           ;-NUMBER OF ASSOCIATED SCALAR QUANTITIES-
 Time                Seconds   ;-INDEPENDENT VARIABLE LABEL: X-
 rho_tor                       ;-INDEPENDENT VARIABLE LABEL: Y-
 NE                  cm^-3     ;-DEPENDENT VARIABLE LABEL-
 0                             ;-PROC CODE- 0:RAW 1:AVG 2:SM. 3:AVG+SM
          1                    ;-# OF X PTS-
         51                    ;-# OF Y PTS-
  2.470000E+00
  0.000000E+00 2.000000E-02 ...
 <данные>
 ;----END-OF-DATA-----------------COMMENTS:-----------
```

Требования `ufheader`/`ufrd` (`read_input.f90`, строки 1226–1342):

| элемент | требование |
|---|---|
| строка 1 | формат `(i7, A4, 1X, i1)`: номер разряда в колонках 1–7, устройство в 8–11, пробел, размерность (1 или 2) в колонке 13. Иначе `wrong dims` / `ERROR STOP` |
| скаляры | `n_scal`, затем `2*n_scal` строк пропускаются |
| метка X | должна начинаться с `TIME`, иначе файл не читается. Единица не `SECONDS` → предупреждение |
| метка Y | только при размерности 2; тип сетки — по §4.2, единица в колонках 21–31 |
| метка функции | одна строка, затем пропуск строки `PROC CODE` |
| размеры | `nt`, затем `nx` (для 2D) — list-directed |
| заголовок при чтении данных | пропускается ровно `2*n_scal + 5 + 2*n_dim` строк |
| времена, сетка | list-directed |
| данные | **строго** `(1X, 6E13.6)`: пробел, затем по 6 чисел шириной 13; время меняется быстрее всего (`arr_out(jt + (jx-1)*nt)`) |

Трёхмерные U-файлы не поддерживаются (`n_dim > 2` → `ERROR STOP`). Путь всегда `udb/` + имя из строки эксперимента (`parse_u_line`, строка 1210). Отсутствие файла даёт `ERROR STOP … opening error`.

### 7.2. `pyparse/ufiles.py`

Модуль Г. Тардини (v0.3.0, 2022), класс `UFILE(dict)`:

| метод | строки | назначение |
|---|---|---|
| `read(fin)` | 70–160 | заголовок разбирается по маркерам `-SHOT #`, `-INDEPENDENT VARIABLE LABEL X-/Y-/Z-`, `-# OF X PTS-` …; данные через `rw_for.ssplit` (понимает «слипшиеся» числа `1.0-2.0`), `reshape(dims[::-1]).T`; поддерживает 1D–3D |
| `average(axis)` | 162–175 | среднее по оси |
| `uslice(val, axis)` | 177–193 | срез |
| `write(udir, dev='AUGD')` | 195–310 | запись в `udir` (по умолчанию `~/udb/<shot>`); существующий файл переименовывается в резервную копию; первая строка `' %6d%4s %1i 0 6 ;-SHOT #- …'`, данные `%13.6E` по 6 в строке с ведущим пробелом, что совпадает с форматом Fortran |
| `plot()` | 312– | быстрый график (matplotlib) |

Python-читатель терпимее Fortran-читателя: числа в данных могут быть в любом формате. **Файл, который прочитал `ufiles.py`, Fortran может не прочитать.** Для записи используйте `UFILE.write` или формат `(1X,6E13.6)`. Пустой файл даёт в `read` исключение `UnboundLocalError` (`ndim` не определён; по коду).

### 7.3. Единицы

Fortran не переводит единицы: значение × `factor` записывается прямо в `X`-переменную. В примерах `udb/34954` метки не соответствуют значениям. `MAG34954.IPL_AVG` помечен `Amps`, но значение 0.797 — это МА. `MAG34954.BTOR_AVG` помечен `Rp*Bt T.cm`, а значение 2.596 похоже на Тл. Нужные единицы ASTRA описаны в [glossary.md](glossary.md), §1: `TE`/`TI` в кэВ, `NE` в 10¹⁹ м⁻³, `IPL` в МА, `BTOR` в Тл, длины в м. Отсюда множители в `aug34954`: `TE … 1.e-3` (эВ → кэВ), `NE … 1.e-13` (см⁻³ → 10¹⁹ м⁻³), `VTOR … 1.e-2` (см/с → м/с).

```text
exp/<exp>, udb/*  ──read_exp──►  raw_scalars (time, data, var_index)      ──set_x_scalars──►  varxValues → IPLX, BTORX, ZRDnX …
                                raw_profiles (группы: time, grid, data)    ──set_x_arrays───►  profiles_x → TEX, NEX, CAR2X …
                                raw_boundary, raw_cCoil, raw_vCoil         ──►  равновесие (06)
```

| шаг | где | когда |
|---|---|---|
| выделение `XAXES`/`DATAX(nr_x_max, n_profx)`, `read_nml`, `config_read(machine)`, имя файла NBI, `equ/log/<model>` | `read_input.f90::readInput` | один раз при старте |
| чтение файла | `read_exp` | один раз |
| `IFDFVX` = 0/1 (эксперимент), затем 2 (модель), 3 (клавиатура), 4 (запрет для `AB AWALL RTOR ELONM TRICH`) | `read_exp`; `detvar.f90`; `astra_assignments` (`set_x_data.f90`, строки 520–523) | — |
| скаляры на текущее время: `varxValues`; при `IFDFVX ≤ 1` также `varValues` | `set_x_scalars` | старт, каждый шаг (`stepup.F90`, строка ~65) |
| профили на сетке ASTRA | `set_x_arrays(1)` при старте, `set_x_arrays(2)` на шаге (`stepup.F90`, строка ~119) | — |
| проверки геометрии (`NA1 ≤ NRD`, `ABC ≤ AB`, `AWALL`), `ABC`/`ELONG` из границы, сетка `HROX = 1/(NA1-0.5)` | `astra_assignments` (строки 488–640) | старт |

Модель получает данные только через `X`-имена: скаляр `IPLX` и профиль `TEX(J)`. Скаляры без `X` (`IPL`, `BTOR` …) из эксперимента попадают в рабочие переменные автоматически, пока модель их не переопределит (`IFDFVX ≤ 1`). Подробнее — [03-model-language.md](03-model-language.md), §5.

## 14. Рекомендации для новой установки (Глобус-М2)

**Это рекомендации, а не описание существующего кода.** Они выведены из разобранного выше поведения парсеров. Числа установки ниже — ориентировочные открытые параметры Глобус-М2 (`R ≈ 0.36 м`, `a ≈ 0.24 м`, `B_t ≤ 1 Тл`, `I_p ≤ 0.5 МА`, `κ ≈ 2`). Их нужно сверить с паспортом установки и данными разряда.

### 14.1. Формат файла эксперимента

1. Держите в скалярной секции только фиксированный формат с пробелами (без табуляций) или свободный `NAMEXP <скаляр> NTIMES n`. Длинные или меняющиеся во времени величины (`IPL`, `BTOR`, `ZRDn`) задавайте U-файлами.
2. Заканчивайте скалярную секцию явной строкой `FILTER 0.001` или `PROFILES` (§3.4).
3. Пишите в каждой управляющей строке все нужные слова: `NAMEXP X POINTS n GRIDTYPE g NTIMES nt`. На наследование не полагайтесь.
4. Давайте каждую величину **одной** группой (все срезы через `NTIMES`).
5. Не превышайте 20 слов и 132 символов в строке: данные по 5–6 чисел в строке, как в `UFILE.write`.
6. Разделяйте поля пробелами. Имя U-строки отделяйте от `U-file:` пробелами, множитель пишите третьим полем: `TE       U-file:41234/TE41234.TS: 1.e-3`.
7. Для профилей из реконструкции (EFIT и т. п.) берите `GRIDTYPE 12` (нормированный `ρ_tor`) или 13 (`ρ_pol`). Для хордовых измерений используйте 18/19 (Томсон по вертикальной/горизонтальной хорде) и 20 (произвольные `R,Z`).

### 14.2. Геометрия сферического токамака

- **`RTOR`, `AB`, `ELONM`, `TRICH`, `AWALL`** задаются в эксперименте и затем заморожены (`IFDFVX=4`). Нужно `ABC ≤ AB`, `AB ≤ AWALL ≤ 1.2·AB`, `AWALL < RTOR`. При `A = R/a ≈ 1.5` последнее условие близко к пределу. Предупреждение `AWALL is set unreasonably large` нужно проверять.
- **Граница.** Задавайте контур сепаратрисы по времени через `BNDU` (U-файлы `_r`/`_z`, время × угол) или `BND`. Тогда `ABC` и `ELONG` вычисляются из контура. `TRIAN` и `SHIFT` нужно задать отдельно (скаляры или модель).
- **`NA1`.** Для начала берите 51–101. Помните, что `NA1 ≤ NRD`.
- **Применимость моделей переноса и равновесия** при малом аспектном отношении — вопрос физики, а не формата. См. [06-equilibrium.md](06-equilibrium.md).

### 14.3. U-файлы

- Пишите U-файлы через `pyparse/ufiles.py::UFILE.write(udir='udb/<разряд>', dev='GLBM')` или эквивалент. Первая строка: номер разряда в 7 колонках, 4 символа устройства, размерность в колонке 13. Данные строго в формате `(1X,6E13.6)`.
- Метки: X — `Time` с единицей `Seconds`; Y — `rho_tor`, `MinorRad` (м), `MajorRad` (м) или `PoloidalFlux`, без лишнего текста в колонках 1–20.
- Сразу пишите значения в единицах ASTRA (кэВ, 10¹⁹ м⁻³, МА, Тл, м) или явно указывайте множитель в exp-строке. Метка единицы в U-файле ни на что не влияет.
- Раскладка: `udb/<разряд>/…`, exp-файл `exp/<машина><разряд>` (например, `exp/gm2_41234`; подчёркивание в имени эксперимента допустимо, в имени машины — нет).

### 14.4. Имя машины и сопутствующие файлы

- Имя `-dev` берите строчными буквами без `_`, например `globus` или `gm2`.
- Положите `exp/nml/<машина>` с минимальным набором namelist'ов. За основу возьмите `exp/nml/aug34954`, уберите модули, которых нет (RABBIT, TORBEAM, SPIDER, STRAHL — закрытые, [DETAILED.md §7](../../installer/docs/DETAILED.md)). Оставьте `equil_settings`, если используется FEQIS.
- Для свободной границы (FEQIS, `IPEQL=5`) нужен `exp/cnf/<машина>_description_in.json` с катушками, лимитером и камерой в формате `aug_description_in.json`. Его можно проверить скриптом `exp/cnf/read_json.py`. Без него используйте режимы с заданной границей ([06-equilibrium.md](06-equilibrium.md)).
- NBI Глобус-М2 описывается в `exp/nbi/<машина>` в формате §10, если подходит модуль `NBI` из `sbr/` ([07-heating-and-external-modules.md](07-heating-and-external-modules.md)).

### 14.5. Порядок проверки нового файла

```bash
# 1) Python-парсер в копии (как в 03, §14); пишет ./data.json с разобранными данными
cd /tmp/astra_try && python3 pyparse/exp_parser.py -exp exp/gm2_41234
# 2) U-файлы: прочитать ufiles.py и сверить первую строку с форматом (i7,A4,1X,i1)
# 3) Сборка: touch equ/<model> (exp не входит в зависимости make)
# 4) Короткий счёт в batch: в выводе не должно быть "not found, skipping",
#    "Unrecognized", "Warning: AWALL", а профили TEX/NEX должны быть ненулевыми
```

Если Python-парсер принял файл, Fortran его ещё может не прочитать (ловушки 2, 3, 9). Если Python отверг файл, Fortran может прочитать его нормально (ловушка 6). Окончательная проверка — только короткий счёт и сравнение `TEX`/`NEX` с исходными данными в графике или выводе ([08-graphics-and-output.md](08-graphics-and-output.md)).
