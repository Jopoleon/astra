## 1. Токамак и разряд за десять минут

### 1.1. Токамак

Токамак — это тороидальная («бублик») вакуумная камера в сильном магнитном поле. Внутри камеры создают плазму: газ (обычно дейтерий) нагрет до температур в сотни и тысячи электронвольт (1 эВ ≈ 11 600 К). Плазму нельзя касаться стенками, её удерживает магнитное поле. Поле складывается из двух частей:

- **тороидальное поле** `B_T` (вдоль «бублика») создают внешние катушки;
- **полоидальное поле** (по малому обходу) создаёт ток, текущий по самой плазме, — **ток плазмы** `I_p`. Его возбуждают как в трансформаторе: плазменный шнур служит вторичной обмоткой, ток в центральном соленоиде меняют, и вдоль тора появляется ЭДС — **напряжение на обходе** `U_loop`.

Силовые линии суммарного поля навиваются на вложенные друг в друга тороидальные **магнитные поверхности**. Вдоль поверхности частицы и тепло разбегаются почти мгновенно, поэтому температура и плотность на каждой поверхности практически постоянны. Медленно идёт только перенос **поперёк** поверхностей, от центра к краю. Поэтому профиль плазмы можно описывать одной радиальной координатой — «номером» поверхности (в ASTRA это `ρ`, нормированный — `XRHO`, см. [glossary](glossary.md)).

Важные геометрические параметры:

| величина | смысл |
|---|---|
| `R` (в ASTRA `RTOR`) | большой радиус: расстояние от оси тора до центра сечения |
| `a` (`AB`, `ABC`) | малый радиус: полуширина сечения плазмы |
| `A = R/a` | аспектное отношение; у классических токамаков ~3, у сферических ~1.5 |
| `κ` (`ELONG`) | вытянутость сечения по вертикали |
| `δ` (`TRIAN`) | треугольность сечения |
| `q` (`1/MU`) | запас устойчивости: сколько раз силовая линия обходит тор по большому кругу за один обход по малому; профиль `q(ρ)` определяется распределением тока |

### 1.2. Разряд

Токамак работает импульсами. Один импульс называется **разрядом** (англ. *shot*, *pulse*) и имеет номер. Подробное объяснение с точки зрения архива данных — в [`tokomak/docs/science/shot-and-machine-overview.md`](../../../tokomak/docs/science/shot-and-machine-overview.md) (`/home/egor/Work/tokomak/docs/science/shot-and-machine-overview.md`).

Стадии разряда:

1. **пробой** — газ ионизуется, появляется плазма;
2. **подъём тока** (*ramp-up*) — ток растёт, профиль тока ещё «не устоялся»;
3. **плато** — ток примерно постоянен, включают дополнительный нагрев (на «Глобус-М2» в основном инжекцию нейтральных атомов, NBI);
4. **спад тока** и окончание разряда.

На «Глобус-М2» разряд длится доли секунды. В цитируемых работах анализируются моменты от 120 до 250 мс от начала разряда ([Тельнова 2021], [Petrov 2022]). Это важно для моделирования: распределение тока за такое время не успевает полностью установиться, поэтому профиль `q` приходится **рассчитывать во времени** (см. §7).

### 1.3. Что измеряют

Для одного разряда записываются десятки и сотни сигналов (см. `docs/science/shot-and-machine-overview.md`, §4). Для транспортного анализа важны следующие измерения. Состав диагностик «Глобус-М2» взят из обзоров [Petrov 2022], [Bakharev 2025] и работ по нагреву.

| диагностика | что даёт | зачем ASTRA |
|---|---|---|
| магнитные зонды, пояс Роговского, петли | `I_p`, `U_loop`, полоидальный поток | граничное условие для уравнения тока; проверка расчёта |
| датчик тороидального поля | `B_T` | параметр модели |
| реконструкция равновесия по магнитным данным | форма последней замкнутой поверхности (сепаратрисы) | граница для 2D-равновесия |
| томсоновское рассеяние лазера (TS) | профили `T_e(ρ)` и `n_e(ρ)` | основной вход для профилей электронов |
| интерферометр | средняя по хорде плотность | нормировка/проверка `n_e` |
| спектроскопия перезарядки (CXRS) | профиль `T_i`, скорость вращения `V_tor` | профиль ионов, вращение |
| анализатор нейтралов перезарядки (NPA) | `T_i`, изотопный состав, спектры быстрых ионов | проверка `T_i`, потери пучка |
| тормозное излучение | эффективный заряд `Z_eff` | плотность ионов и проводимость |
| болометры | излучённая мощность `P_rad` | сток энергии |
| диамагнитная петля | энергозапас `W` | проверка интегрального баланса |
| нейтронные детекторы | нейтронный выход | проверка быстрых ионов пучка |
| мягкий рентген (SXR) | пилообразные колебания | проверка момента появления поверхности `q = 1` |
| допплеровское обратное рассеяние (ДОР, DBS) | флуктуации плотности, вращение, моды | физика турбулентности; в ASTRA напрямую обычно не входит |
| параметры инжекторов NBI | мощность, энергия, состав пучка, геометрия | источник нагрева, тока и частиц |

## 2. Что такое транспортное моделирование

### 2.1. Задача

Плазму нагревают (омический нагрев током, пучки, волны), а тепло и частицы уходят от центра к краю и дальше на стенку. Интенсивность утечки называется **переносом** (*transport*). Если бы перенос шёл только за счёт столкновений частиц, его можно было бы посчитать по формулам **неоклассической теории**. В реальности перенос обычно во много раз сильнее из-за мелкомасштабной турбулентности. Такой перенос называют **аномальным**, и надёжной теории, предсказывающей его во всех режимах, нет. Руководство ASTRA прямо говорит, что моделирование переноса «в значительной степени эмпирическое» и идёт методом проб и ошибок (`docu/section12.tex`, Introduction).

**Транспортный код** решает уравнения баланса частиц, энергии и магнитного потока, усреднённые по магнитным поверхностям. По радиусу они одномерные, а геометрию поверхностей берут из двумерного уравнения равновесия (Грэда–Шафранова). Такую систему называют **1.5D** (`docu/section12.tex`; подробно — [05-solver-core.md](05-solver-core.md), [06-equilibrium.md](06-equilibrium.md)).

### 2.2. Уравнение баланса энергии на пальцах

Упрощённо, для электронов:

\[
\tfrac{3}{2}\,\frac{\partial (n_e T_e)}{\partial t}
= -\frac{1}{V'}\frac{\partial}{\partial \rho}\bigl(V' q_e\bigr) + P_e,
\qquad
q_e \approx -\,n_e\,\chi_e\,\langle|\nabla\rho|^2\rangle\,\frac{\partial T_e}{\partial \rho}.
\]

Здесь `P_e` — источники минус стоки (омический нагрев, нагрев пучком, обмен с ионами, излучение), `q_e` — поток тепла через поверхность, `V'` — производная объёма по радиусу. Неизвестное в этой формуле — **коэффициент температуропроводности** `χ_e` (м²/с): насколько легко тепло «просачивается» поперёк поверхностей. Для ионов есть аналогичное уравнение с `χ_i`, для частиц — коэффициенты диффузии `D` и пинча `V`. Для тока — уравнение диффузии полоидального потока с проводимостью плазмы (её считают неоклассической).

В ASTRA эти коэффициенты называются `HE` (`χ_e`), `XI` (`χ_i`), `DN` (`D`) и т. д. Значения задаёт **модель** (файл `equ/<модель>`), см. [03-model-language.md](03-model-language.md).

### 2.3. Зачем это нужно

- **Измерить невидимое.** `χ_e`, `χ_i` и энергетический баланс диагностики не измеряют, их восстанавливают из измеренных профилей и рассчитанных источников. Профиль тока и `q(ρ)` тоже почти не измеряются напрямую.
- **Сравнить режимы.** Время удержания энергии `τ_E` и коэффициенты переноса позволяют сравнивать разряды и установки между собой и строить **скейлинги** (эмпирические степенные законы для `τ_E`).
- **Проверить теорию.** Сравнить восстановленный `χ` с неоклассическим или с теоретической моделью турбулентности (например, TGLF).
- **Предсказать.** Оценить параметры будущего режима или установки (в ФТИ — проект «Глобус-3», см. §7.4) до эксперимента.
- **Интерпретировать диагностики.** Нейтронный выход, сигналы NPA и SXR надо сопоставлять с рассчитанными распределениями быстрых ионов и профилем `q`.

ASTRA (*Automated System for TRansport Analysis*) создана в конце 1980-х в Курчатовском институте (Г. В. Переверзев, П. Н. Юшманов) и развивается в IPP Garching. Это не готовая программа, а система, которая **собирает транспортный код под задачу** из модели пользователя (`docu/section12.tex`, Overview; подробно — [01-overview.md](01-overview.md), [02-build-and-run.md](02-build-and-run.md)).

## 3. Интерпретационный и предсказательный режимы

В ASTRA нет переключателя «режим». Режим определяется тем, **как модель обращается с каждой величиной** ([01-overview.md §9.3](01-overview.md), [03-model-language.md §6](03-model-language.md)).

### 3.1. Интерпретационный режим (анализ баланса мощности)

Профили, которые измерены, **присваиваются** из эксперимента, а не рассчитываются:

```
TE:AS;   TE=TEX;      ! Te берётся из данных (TEX — экспериментальный профиль)
NE:AS;   NE=NEX;
```

Код считает всё, что не измерено:

- источники: омический нагрев, нагрев пучком, обмен энергией между электронами и ионами, излучение;
- полный поток тепла через каждую поверхность — интеграл источников по объёму;
- эффективные коэффициенты переноса из баланса мощности, «поток / градиент». В пользовательской области для этого есть готовые формулы: `HEEFF` и `XIEFF` («effective electron/ion heat conductivity», `repo_user_area/fml/heeff`, `fml/xieff`) и `HEXP` («experimental electron heat conductivity» по `TEX`, `fml/hexp`);
- диффузию тока (`CU:EQ`), то есть профили `j(ρ)` и `q(ρ)` во времени, напряжение на обходе;
- интегральные величины: энергозапас `WTOT` (`fnc/wtot.f90`), `τ_E` = `TAUE` = `W/(P − dW/dt)` (`fnc/taue.f90`).

Именно так устроена тестовая модель `equ/flux_feqis` из репозитория: `TE`, `TI`, `NE` присвоены из U-файлов разряда AUG #34954, решается только уравнение тока, равновесие считает FEQIS:

```
TE:AS;		TE=TEX;
TI:AS;		TI=TIX
NE:AS;		NE=NEX;
...
CU:EQ;
CC=CNSA;            ! неоклассическая проводимость
MU=1./(CAR2X + 0.0001);   ! начальный q из данных (CAR2X ← Q34954.QPR)
```

(`repo_user_area/equ/flux_feqis`.) Поэтому в её результате `HE` и `XI` равны нулю: уравнения энергии не решались. Зато рассчитаны `CU`, `MU`, `UPL`, равновесие.

### 3.2. Предсказательный режим

Профили **рассчитываются** из уравнений (`TE:EQ;`), а коэффициенты переноса задаёт модель:

- неоклассический перенос (модуль NCLASS, `repo_user_area/sbr/nclass_mod.f90`);
- эмпирическая модель или скейлинг;
- теоретическая модель турбулентности: TGLF, QuaLiKiZ, нейросеть QLKNN (через IPC, [07-heating-and-external-modules.md §12–13](07-heating-and-external-modules.md)). В нашей сборке TGLF, QuaLiKiZ и QLKNN **пока не установлены** (`installer/docs/DETAILED.md`, §7).

Затем расчётные профили сравнивают с измеренными. Если они совпадают, модель переноса правдоподобна, и её можно использовать для прогноза. В IPP так проверяют связку ASTRA + TGLF на ASDEX Upgrade [Angioni 2022], [Tardini 2021], [Erofeev]. В предельном случае задаются только «инженерные» параметры (ток, поле, мощность, граница, напуск газа), а профили и энергозапас предсказываются целиком (подход IMEP, [Tardini 2021]).

### 3.3. Смешанный режим — самый частый на практике

Обычно часть величин присвоена, часть рассчитана. Примеры из работ по «Глобус-М/М2»:

- **Электроны — интерпретационно, ионы — предсказательно.** `T_e`, `n_e` из томсоновского рассеяния присвоены. `T_i` рассчитывается с `χ_i = χ_i^neo` (неоклассика по NCLASS) и сравнивается с CXRS/NPA. Если расчётный `T_i` и энергозапас ионов выше измеренных, ионный перенос аномальный ([Kurskiev 2023], разд. про ASTRA; [Telnova 2020]).
- **Подбор свободного параметра.** Коэффициент диффузии частиц `D` подбирали так, чтобы рассчитанный `n_e` совпал с измеренным в пределах ошибок, а пинч задавали формулой Веера ([Тельнова 2021], разд. 4).
- **Подбор аномальной диффузии быстрых ионов.** Её подбирают в расчёте NBI так, чтобы совпал нейтронный выход или энергозапас ([Kurskiev 2023], расчёт NUBEAM для #41585).

### 3.4. Сводка

| | интерпретационный | предсказательный |
|---|---|---|
| профили `T_e`, `T_i`, `n_e` | из эксперимента (`:AS`) | из уравнений (`:EQ`) |
| коэффициенты переноса | **результат** (из баланса) | **вход** (модель, NCLASS, TGLF, …) |
| что сравнивают с экспериментом | ток, `U_loop`, `W`, нейтроны, момент `q = 1` | профили, `W`, `τ_E` |
| что даёт | «фотографию» переноса в данном разряде | проверку модели, прогноз |
| требования к данным | высокие: нужны хорошие профили | ниже: достаточно граничных условий и источников |
| пример в репозитории | `equ/flux_feqis` | модели `equ/tglf*`, `equ/qlk*`, `equ/imep_*` ([09-user-area-catalog.md](09-user-area-catalog.md)) |

## 4. Входные данные: от диагностики до механизма ASTRA

### 4.1. Механизмы ввода

ASTRA разделяет **модель** (как считать) и **данные** (что считать) — `docu/section5.tex`, §5.1 «General concept». Данные приходят через:

| механизм | где лежит | что в нём | подробно |
|---|---|---|---|
| файл эксперимента | `exp/<имя>` | геометрия камеры, скаляры, ссылки на U-файлы, граница, токи катушек | [04-experiment-data.md](04-experiment-data.md) |
| U-файлы | `udb/<разряд>/…` | временные ряды (1D) и профили по времени (2D) в ASCII-формате UFILES (PPPL) | [04 §7](04-experiment-data.md) |
| namelist | `exp/nml/<exp>` или `exp/nml/<machine>` | параметры модулей: RABBIT, NBI, TORBEAM, `equil_settings` | `docu/addendum_A8.tex`, «The namelist files» |
| описание машины | `exp/cnf/<machine>_description_in.json` | катушки, лимитер, камера; нужно только для свободной границы FEQIS | [06-equilibrium.md §6](06-equilibrium.md) |
| конфигурация NBI | `exp/nbi/<exp>` | геометрия и параметры пучков для встроенного модуля NBI | [07 §5](07-heating-and-external-modules.md) |
| стартовые параметры модели | `equ/log/<модель>` | переменные, константы `CF*`, `CV*`, управляющие параметры (`DPOUT`, …) | [11 §3](11-usage-guide.md) |
| модель | `equ/<модель>` | уравнения, формулы, что выводить | [03](03-model-language.md) |

Экспериментальная величина в ASTRA обычно имеет суффикс `X`: `TEX`, `NEX`, `TIX`, `IPLX`, `ZEFX`, `VTORX`. Произвольные «пустые» каналы — `CARnX` (профили) и `ZRDnX` (временные ряды). Модель решает, что с ними делать.

### 4.3. Равновесие и граница

Транспортным уравнениям нужна метрика магнитных поверхностей: объёмы, площади, средние `⟨|∇ρ|²⟩`. Её даёт двумерное равновесие ([06-equilibrium.md](06-equilibrium.md)). Варианты:

- **граница из эксперимента + решатель ASTRA** (FEQIS при `IPEQL=5` с фиксированной границей). Так устроены `flux_feqis`/`aug34954` и, судя по публикациям, расчёты «Глобус-М2»: границу «последней замкнутой поверхности» берут из магнитной реконструкции методом подвижных токовых колец, а внутреннее равновесие ASTRA считает сама ([Тельнова 2021], [Kurskiev 2023], [Petrov 2022]). В A7 для этого служил SPIDER; в A8 SPIDER — закрытый модуль IPP, и его свободная граница больше не поддерживается (`docu/addendum_A8.tex`, «Equilibrium solvers»);
- **метрика целиком извне** (`IPEQL=-1`/`-6`): профили `SHX`, `ELX`, `TRX`, `G11X`, … из файла эксперимента или `input_metric.dat` (`docu/addendum_A8.tex`);
- **свободная граница** (FEQIS FBE): нужно описание машины `exp/cnf/<machine>_description_in.json`. Для «Глобус-М2» его пока нет (§11).

Для реконструкции равновесия «Глобус-М2» использует несколько инструментов. Метод токовых колец определяет форму границы в паузе между разрядами. Код со свободной границей pyGSS [Kiselev 2023] и сравнение с кодом PET описаны там же. Старая программа просмотра лаборатории умеет читать результаты EFIT: файлы `a%06d.?????` (скаляры) и `g%06d.?????` (равновесие) — `tokomak/viewer/WORKFLOW_DEEP_DIVE.md`, «EFIT And A-Files»; `viewer/src/combiscope/CPP/efit_browser.cpp`, строка 2624. EFIT g-file (формат EQDSK) — стандартный источник границы и профиля `q`. В A8 есть обратный конвертер ASTRA → EQDSK (`postProcess/json2eqdsk.py`).

## 5. Выходные данные и что с ними делают

### 5.1. Куда пишется результат

В A8 ядро каждые `DPOUT` секунд модельного времени пишет снимок всех переменных в `ncdf_out/<exp><model>-<k>.json`. После расчёта `postProcess/json2cdf.py` склеивает снимки в один NetCDF-файл `ncdf_out/<exp><model>.CDF` (`src/astra/astra_main.F90`, строки 122–125; `exe/as_exe.py`, строка 149; подробно — [08-graphics-and-output.md §6–9](08-graphics-and-output.md)).

Проверено на тестовом расчёте `flux_feqis`/`aug34954`, `-s 4 -e 5`, 2026-10-01. В файле 6 временных срезов (4.0, 4.2, …, 5.0 с при `DPOUT=0.2` из `equ/log/flux_feqis`), 91 радиальная точка и **1137 переменных** — практически все массивы и скаляры ядра, а не только то, что выведено на экран. Выражения из секций вывода модели (например, `hexp\HEXP`) в CDF **не попадают**. Чтобы сохранить производную величину, её присваивают «пустому» массиву `CARn` или скаляру `CFn`. Так в `flux_feqis` сделано `CAR1 = QETOT` и `CF8 = NEC/NEAVB`. Практика — в [11-usage-guide.md §4.7](11-usage-guide.md).

### 5.2. Что физики извлекают из результата

| результат | переменные ASTRA (примеры) | как используют |
|---|---|---|
| энергозапас `W` | `WTOT` (формула, `fnc/wtot.f90`), `WTE`/`WTI` | сравнивают с диамагнитным `W`; разница ~10 % — оценка давления быстрых ионов [Тельнова 2021] |

| нейтронный выход | `NRATE` (плотность), интеграл по объёму | сравнивают с детекторами; без учёта вращения выход занижается на ~15 % [Zenkova 2024] |

| входные данные для других кодов | профили `T`, `n`, `q`, вращения | линейная гирокинетика GENE на «Глобус-М2» [Kiselev 2025]; SOLPS для края |

## 6. Типичный путь: от разряда до результата

Ниже — обобщённый путь, собранный из постановки расчётов в работах лаборатории ([Тельнова 2021], [Kurskiev 2023], [Petrov 2022], [Bakharev 2025]). Конкретные внутренние скрипты лаборатории нам не известны (§8).

```
 разряд #N в архиве (.SHT, .DAT, TS, CXRS, NPA, EFIT/границы)
        │
        ▼
 1. выбор разряда и окна времени (плато, квазистационарная фаза, до МГД-событий)
        │
        ▼
 2. сбор и обработка сигналов:
      I_p, B_T, U_loop, W_dia, n_e(инт.), нейтроны   → временные ряды
      T_e, n_e (Томсон), T_i, V_tor (CXRS/NPA)        → профили по времени, сглаживание/фит
      Z_eff, P_rad                                    → профили или константы
        │
        ▼
 3. равновесие: граница из метода токовых колец / pyGSS / EFIT
        │
        ▼
 4. нагрев пучком: NUBEAM (вне ASTRA) → профили поглощённой мощности P_e, P_i,
      тока, частиц; учёт потерь (плохие орбиты, перезарядка, прострел)
        │
        ▼
 5. подготовка входа ASTRA: exp/<имя>, udb/<разряд>/*.U-файлы, exp/nml, модель equ/<имя>
        │
        ▼
 6. серия расчётов ASTRA: интерпретационный → подбор свободных параметров
      (D, аномальная диффузия быстрых ионов, χ_i) → сравнение с W_dia, U_loop,
      нейтронами, T_i, моментом q=1
        │
        ▼
 7. результат: τ_E, χ_e, χ_i, баланс мощности, q(ρ,t), доля безындукционного тока
        │
        ▼
 8. сравнение со скейлингами и между разрядами, гирокинетика, статья
```

Пример реальной постановки ([Тельнова 2021], разд. 4, разряды #38032/#38038/#38047):

- расчёт с 120 мс до развития МГД-неустойчивостей (155 мс);
- вход: ток плазмы, напряжение на обходе, ионная температура, профили `T_e` и `n_e` по времени (Томсон), параметры и геометрия пучка;
- `Z_eff ≈ 2.5` из измерений, проводимость неоклассическая (NCLASS);
- граница — магнитная реконструкция методом подвижных токовых колец;
- концентрация нейтралов на границе ~10¹⁷ м⁻³ — кодом DOUBLE по данным NPA;
- поглощённая мощность пучка — блоком NBI, прямые потери — поправочным коэффициентом из орбитального 3D-кода;
- `D` — свободный параметр, подобранный по совпадению профиля `n_e`.

Обычно расчётов в такой серии десятки. Каждый занимает минуты (тестовый `flux_feqis` на нашей машине — 30 с на 1 с модельного времени при шаге 50 мс, 99 % времени уходит на равновесие FEQIS, см. вывод `Astra wall time` в [11 §4.3](11-usage-guide.md)).

## 7. Сферический токамак и особенности «Глобус-М2»

### 7.1. Параметры

| параметр | значение | источник |
|---|---|---|
| большой радиус `R` | 0.36 м | [Bakharev 2025], [Petrov 2022] |
| малый радиус `a` | 0.24 м (0.22 м в отдельных разрядах) | [Bakharev 2025]; [Kurskiev 2022b] |
| аспектное отношение `A` | ~1.5–1.6 | там же |
| вытянутость `κ` | ~1.8–2 | [Zenkova 2024], [Kurskiev 2023] |
| тороидальное поле `B_T` | до 0.95 Тл сейчас, проектное 1 Тл | [Bakharev 2025] |
| ток плазмы `I_p` | до 450 кА сейчас, проектный 500 кА | [Bakharev 2025] |
| дополнительный нагрев | 2 инжектора NBI, каждый до 1 МВт; энергии 18–50 кэВ; также ВЧ-нагрев (ICRH) и генерация тока нижнегибридными волнами (LHCD, 2.45 ГГц) | [Bakharev 2025], [Petrov 2022], обзор STW-2022 |
| первая стенка | графит → основная примесь углерод | [Kurskiev 2023] |
| предшественник | «Глобус-М» (0.4–0.5 Тл) | [Kurskiev 2017], [Gusev 2013] |

### 7.2. Что особенного для моделирования

- **Малое аспектное отношение и сильная вытянутость.** Приближённые описания геометрии (цилиндр, малые поправки по `a/R`) неприменимы. Нужно полноценное двумерное равновесие с заданной границей, в A8 — FEQIS ([06-equilibrium.md](06-equilibrium.md)). В публикациях ASTRA решает уравнение Грэда–Шафранова вместе с диффузией потока ([Kurskiev 2023]).
- **Быстрые ионы пучка теряются.** Компактная установка, а ларморовский радиус быстрых ионов сопоставим с размерами плазмы. Поэтому значительная часть мощности пучка теряется: на «плохих» орбитах, при перезарядке на нейтралах, при прострелах. На слайдах STW-2022 для разряда #41585 приведены доли потерь: CX 200 кВт, плохие орбиты 50 кВт, прострел 10 кВт при поглощении на ионах 300 кВт и на электронах 140 кВт. Поэтому нагрев пучком на «Глобус-М2» считают **кодом NUBEAM с отслеживанием орбит** и отдельными 3D-расчётами потерь, а не простыми моделями отложения ([Petrov 2022], [Kurskiev 2023]).
- **Режим горячих ионов.** При NBI и `B_T ≥ 0.7` Тл ионы горячее электронов: `T_i` до 4–4.7 кэВ при `T_e` 1–1.7 кэВ ([Kurskiev 2022b], [Bakharev 2025]). Ионный перенос часто близок к неоклассическому, поэтому для ионов важен качественный неоклассический модуль (NCLASS).
- **Сильное вращение.** CXRS видит тороидальное вращение до 190 км/с ([Zenkova 2024]). Вращение и радиальное электрическое поле меняют распределение быстрых ионов и нейтронный выход, поэтому в лаборатории сделали совместный расчёт ASTRA + NUBEAM с переносом момента (там же).
- **Короткий разряд.** Длительность плато сравнима со временем установления профиля тока или меньше его, поэтому `q(ρ,t)` нужно рассчитывать во времени, начиная с подъёма тока ([Тельнова 2021]). Для «Глобус-3» именно превышение длительности плато над временем установления (`Δt_plateau > τ_L/R`) назвали ключевым условием выбора параметров [Mineev 2022].
- **Скейлинги отличаются от классических токамаков.** `τ_E` сильно растёт с полем (`∝ B_T^1.23`) и слабо с током ([Kurskiev 2022]). При бо́льших полях рост, по-видимому, насыщается на H-факторе ~1.4 (сравнение с ST40, [Bakharev 2025]). Поэтому прогноз для будущих сферических токамаков по скейлингам делают с оговорками (там же).
- **Пилообразные колебания и МГД.** Окно расчёта часто обрывают на появлении МГД-неустойчивостей. Модель пилообразных колебаний (`MIXINT` в моделях, `repo_user_area/sbr/mixint.f90`) влияет на центральный `q`.
- **Применимость теоретических моделей турбулентности.** TGLF и QuaLiKiZ калибровались в основном на классических токамаках. Насколько они пригодны при `A ≈ 1.5`, — вопрос физики. В найденных работах по «Глобус-М2» турбулентность изучали линейной гирокинетикой (код GENE), а не TGLF внутри ASTRA ([Kiselev 2025], [Tkachenko 2025]). Использования TGLF для «Глобус-М2» мы в открытых источниках **не нашли**.

### 7.3. Кто в лаборатории занимается моделированием (по публикациям)

В работах с ASTRA регулярно встречаются: Г. С. Курскиев, А. Ю. Тельнова, Н. Н. Бахарев, П. Б. Щёголев, Е. О. Киселев, В. Б. Минаев, Ю. В. Петров, В. К. Гусев, Н. В. Сахаров, Е. Е. Ткаченко, О. А. ### 7.4. «Глобус-3»

«Глобус-3» — следующий сферический токамак ФТИ: `R₀ = 0.775` м, `a = 0.44` м, `A ≈ 1.76`, `B_T = 1.5` Тл (с возможным повышением до 1.8–2 Тл), `I_p = 0.8` МА (предельный сценарий 2 МА), плато 2–3 с, NBI 10–12 МВт ([Minaev 2023], [Minaev 2025], [Bakharev 2025]). Параметры выбирали инженерно-физическим кодом GLOBSYS [Mineev 2022]. Оценки температур в [Bakharev 2025] сделаны по скейлингу IPB98(y,2). Публикаций с **предсказательным ASTRA-моделированием «Глобус-3»** мы не нашли (поиск 2026-10-01). Это естественная будущая задача для ASTRA 8 с TGLF/QLKNN, но не подтверждённый факт.

## 8. Что известно о работе лаборатории с ASTRA

### 8.1. Факты (из переписки и рабочих материалов)

- У лаборатории работает **ASTRA 7.02** под WSL с X11-окном (скриншоты от 2026-09-30, `docs/research/astra-a8-install-research-2026-10-01.md` монорепозитория). Нужна ASTRA 8 на чистой Ubuntu.
- Для проверки установки лаборатория назвала «hello world» `astra readme showdata` и пример `flux_feqis`/`aug34954`.
- Лаборатория обещала прислать рабочую пару файлов: модель `NBI_nubeam_Int_CXRS.model` и данные `DBS_HD_lown0.data` (`AGENTS.md` монорепозитория, раздел «Лаборатория»). На 2026-10-01 файлов у нас нет.
- В публикациях указан инструментарий: «ASTRA 7.0, NCLASS, SPIDER, NUBEAM, 3D fast ion tracking algorithm» ([Petrov 2022], аннотация). Для совместного расчёта ASTRA + NUBEAM написана отдельная программа на Python ([Zenkova 2024] и связанная с ней квалификационная работа; авторство второй карточки не проверено).
- На NAS лаборатории (Synology, адрес — в `tokomak`) среди rsync-модулей видны `ASTRA`, `EFIT`, `TS`, `CX_NPA`, `Neutron`. Содержимое закрыто (`tokomak/docs/analysis/lab-accessible-storage-inventory-2026-05-07.md`). Что лежит в `ASTRA` и `EFIT`, неизвестно.

### 8.2. Расшифровка имён файлов — **предположение**

| фрагмент | вероятный смысл | на чём основано |
|---|---|---|
| `NBI_…` | модель с нагревом нейтральной инжекцией | основной нагрев «Глобус-М2» |
| `…nubeam…` | источники пучка из NUBEAM, вероятно как готовые профили или через внешнюю связку | публикации; в исходниках ASTRA 8 слова `nubeam` нет (`rg -i nubeam` по `astra-src` без `docs/` — пусто) |
| `…Int…` | «interpretive» (интерпретационный расчёт) **или** «integrated» (интегральная связка с NUBEAM) | оба термина используются в работах лаборатории |
| `…CXRS` | профиль `T_i` и/или вращения из CXRS | диагностика «Глобус-М2» |
| `DBS_…` | данные разряда из серии с ДОР (DBS) | на «Глобус-М2» активно используют ДОР (L-H переход, ELM, альфвеновские моды, [Bakharev 2025]) |
| `…HD…` | изотопный состав: например, H-пучок в D-плазме | в работах сравниваются H- и D-инжекция [Tkachenko 2025] |
| `…lown0` | «low n₀» — низкая плотность нейтралов, или «low n» — низкая плотность | только по имени |
| расширения `.model`/`.data` | нестандартные: в ASTRA модель и данные — файлы без расширения в `equ/` и `exp/` | `docu/section5.tex`, §5.5.2; в A8 имя передаётся как есть (`exe/as_exe.py`) |

### 8.3. Что это значит для перехода на A8

- **NUBEAM не входит ни в ASTRA 7, ни в ASTRA 8.** Если модель лаборатории получает нагрев пучком из NUBEAM, должен существовать внешний мостик: файлы с профилями или программа-связка. Его нужно перенести вместе с моделью. Если NUBEAM даёт профили, их естественно подавать в A8 через `PEX`/`PIX`/`CUX`/`SNX` или `CARnX` (§4.2). Это не проверено на данных лаборатории.
- **SPIDER в A8 закрыт**, и его свободная граница убрана. Модели A7 с `IPEQL` для SPIDER придётся перевести на FEQIS с фиксированной границей (`IPEQL=5`) или на внешнюю метрику. Тест `flux_feqis` показывает, что FEQIS с границей из U-файлов работает в нашей сборке без закрытых модулей.
- **NCLASS есть в A8** (`repo_user_area/sbr/nclass_mod.f90`).
- **Встроенный модуль NBI** (`src/nbi`, `sbr/nbi.f90`) в A8 есть ([07 §5](07-heating-and-external-modules.md)). Насколько он пригоден для «Глобус-М2» с его потерями на орбитах, — вопрос к лаборатории.
- Практический порядок миграции — в [11-usage-guide.md §7](11-usage-guide.md).

## 9. Архив MDSplus как источник данных для ASTRA (предложение)

**Весь раздел — предложение.** В проекте `tokomak` сейчас нет кода, связывающего архив с ASTRA. Поиск `astra`, `U-file`, `ufile` по репозиторию (без `mdsplus-alpha`, `node_modules`, `artifacts`) находит только документацию по установке ASTRA. EFIT упоминается только в старой программе просмотра и в планах.

### 9.1. Что уже есть в архиве

По `tokomak/AGENTS.md` и `docs/context/project-context.md`:

- сырые сигналы разряда в `.RAW.SOURCES.<FAMILY>.SIGS` (семейства `FAM_SHT`, `FAM_MHD`, `FAM_DAT`) — в основном магнитные и электротехнические сигналы, токи и напряжения цепей;
- обработанные сигналы в `.PROCESSED` (правила старого `process.cnf`);
- происхождение (файл, sha256, версия парсера) в `.PROVENANCE.SOURCES`;
- быстрые счётчики в `.INDEX`.

Профилей Томсона, CXRS, `Z_eff` и границ EFIT в архиве **пока нет**. На NAS они, вероятно, лежат в модулях `TS`, `CX_NPA`, `EFIT` (§8.1).

### 9.2. Предлагаемая цепочка

```
MDSplus (дерево globusm2, разряд N)
  .RAW / .PROCESSED: Ip, Bt, Uloop, Wdia, нейтроны, NBI (мощность, энергия)
  будущие ветки: TS-профили, CXRS, Zeff, граница/EFIT
        │   tools/astra/export_shot.py  (нет; предложение)
        ▼
  ~/astra/a8/udb/<N>/*.U-файлы      ← pyparse/ufiles.py :: UFILE.write(udir=..., dev='GLBM')
  ~/astra/a8/exp/gm2_<N>            ← шаблон exp-файла (04 §14)
  ~/astra/a8/exp/nml/gm2_<N>        ← при необходимости
  provenance.json                   ← узлы MDSplus, версии, sha256 U-файлов
        │   astra8 -m <модель> -v gm2_<N> -s t0 -e t1 -batch
        ▼
  ncdf_out/gm2_<N><модель>.CDF
        │   tools/astra/import_result.py (нет; предложение)
        ▼
  MDSplus .PROCESSED.<короткое имя ветки ASTRA> (+ .PROVENANCE, .QUALITY)
```

Принципы (из правил `tokomak/AGENTS.md`):

- **Экспорт и импорт — явные CLI-действия**, не побочный эффект просмотра.
- **Происхождение.** У каждого U-файла записаны узел MDSplus, номер разряда, версия экспортёра, преобразования (сглаживание, фит, единицы). У каждого результата ASTRA записаны коммит ASTRA, модель, `equ/log`, `tmp/astra.nml` и sha256 входов.
- **Результаты моделирования — это обработанные данные.** Новые данные идут в `.PROCESSED`, не в `.DERIVED`. Имена узлов короткие, ASCII, документируются в `docs/references/mdsplus-node-naming.md`; конкретные имена пока не выбраны.
- **Не портить исходники.** `.SHT`/`.DAT` не трогаем, U-файлы — производные артефакты.

### 9.3. Черновик соответствия «узел → вход ASTRA»

| величина | в архиве сейчас | вход ASTRA | преобразование |
|---|---|---|---|
| `I_p(t)` | сырой/обработанный сигнал (`.RAW`/`.PROCESSED`) | U-файл 1D → `IPL` | А → МА, сглаживание, обрезка окна |
| `B_T(t)` | сигнал тока катушек или поля | U-файл 1D → `BTOR` | ток катушек → поле на `RTOR` (коэффициент установки) |
| `U_loop(t)` | сигнал петли | U-файл 1D → `ZRDnX` | для сравнения с `UPL` |
| `W_dia(t)` | обработанный сигнал (если есть) | U-файл 1D → `ZRDnX` | для сравнения с `WTOT` |
| мощность NBI | сигналы инжекторов | U-файл 1D → `QNBIX` / `pinj_file` | кВт → МВт; поглощённая мощность — отдельно, из NUBEAM |
| `T_e`, `n_e` (Томсон) | нет | U-файл 2D → `TEX`, `NEX` | `R` → `ρ` по равновесию, фит, эВ → кэВ, м⁻³ → 10¹⁹ м⁻³ |
| `T_i`, `V_tor` (CXRS) | нет | U-файл 2D → `TIX`, `VTORX` | то же |
| граница | нет (EFIT/токовые кольца на NAS?) | `BNDU` (пара U-файлов `_r`/`_z`) | контур по времени, `θ`-сетка |

**Самая трудная часть — профили.** Томсон и CXRS измеряют в точках `(R, Z)`, а ASTRA нужен профиль по `ρ`. Для отображения нужно равновесие: EFIT, pyGSS или граница плюс ASTRA. ASTRA умеет сама принимать хордовые данные (`GRIDTYPE` 18–20, [04 §5](04-experiment-data.md)). Возможно, проще передавать точки `(R, Z)` и поручить отображение ASTRA. Это открытый вопрос к лаборатории.
