## 1. Быстрый старт

Проверочный расчёт после установки (модель `flux_feqis`, данные разряда ASDEX Upgrade #34954, окно 4–5 с, без окна GUI):

```bash
astra8 -m flux_feqis -v aug34954 -s 4 -e 5 -batch
ls -l ~/astra/a8/ncdf_out/aug34954flux_feqis.CDF
```

Успех определяется **двумя** признаками: в выводе есть строка `>>> ASTRA normal exit >>>`, и появился свежий файл `ncdf_out/<эксперимент><модель>.CDF`. Код возврата команды ничего не значит: `as_exe` возвращает 0 даже при `ERROR STOP` в Фортране (проверено: см. §6.4, первый запуск).

Тот же расчёт с окном (нужен X-сервер, в WSL это WSLg):

```bash
astra8 -m flux_feqis -v aug34954 -s 4 -e 5
```

Окно не закрывается само по достижении конца. Выход — клавиша `/` (не `Esc`), см. §5.

## 2. Запуск расчёта

### 2.1. Что делает команда `astra8`

`astra8` — обёртка установщика в `~/.local/bin/astra8`. Она выставляет `ASTRA_PLATFORM=ubuntu` и `AWD=~/astra/a8` (рабочий каталог ASTRA) и вызывает `exe/as_exe`. Дальше по цепочке:

1. `exe/as_exe.py` разбирает ключи и записывает их в `tmp/astra.nml`;
2. `exe/Build` пересобирает программу под модель: парсер `pyparse` генерирует Фортран в `src/tmp/`, `make` собирает `bin/<модель>_batch.exe` или `bin/<модель>_gui.exe`;
3. запускается исполняемый файл; он пишет снимки состояния `ncdf_out/<эксп><модель>-<k>.json`;
4. `json2cdf` склеивает снимки в `ncdf_out/<эксп><модель>.CDF` (вызов в `exe/as_exe.py`, строка 149).

Каждый новый расчёт **компилирует модель**: модель ASTRA — это программа, а не входной файл (подробно — [02](02-build-and-run.md), [03](03-model-language.md)). Первая сборка новой модели занимает несколько секунд, повторная без изменений почти мгновенна.

### 2.2. Ключи

Ключи определены в `exe/as_exe.py` (строки 44–68):

| ключ | смысл | по умолчанию при первом запуске | запоминается в `tmp/astra.nml` |
|---|---|---|---|
| `-m <модель>` | файл модели из `equ/` | обязателен | да |
| `-v <эксп>` | файл эксперимента из `exp/` | обязателен | да |
| `-s <t>` | начальное время, с | 0.1 | да |
| `-e <t>` | конечное время, с | 10 | да |
| `-batch` | без окна (иначе GUI) | GUI | **нет** |
| `-dev <имя>` | короткое имя машины (`aug`, …); влияет на выбор `exp/nml/<машина>` и т. п. | `aug` | да |
| `-resize <k>` | масштаб окна GUI | 1 | да |
| `-c <gcc\|ifx>` | компилятор | из `platform/env.*` | да |
| `-tpause <t>` | пауза GUI на времени `t` | 1e4 | нет |
| `-debug` | отладочная сборка | выкл. | нет |
| `-re <n>` | рестарт | 0 | нет |
| `-fs` | «flight simulator» (режим AUG) | выкл. | нет |
| `-workflow <файл>` | свой `stepup.F90` вместо стандартного | `src/astra/stepup.F90` | нет |
| `-nodes <n>`, `-W` | параметры SLURM | 1, выкл. | нет |

Следствия, которые легко пропустить:

- **`astra8` без ключей повторяет последний расчёт** (модель, эксперимент, окно по времени берутся из `tmp/astra.nml`), но **в режиме GUI**, потому что `-batch` не запоминается.
- Если указать только `-m`, эксперимент останется прежним. Так же в A7 работала команда `Astra , analysis`.
- Если `tmp/astra.nml` нет (свежая установка), `-m` и `-v` обязательны.

### 2.3. Batch и GUI

| | batch (`-batch`) | GUI |
|---|---|---|
| исполняемый файл | `bin/<модель>_batch.exe` | `bin/<модель>_gui.exe` |
| X-сервер | не нужен | нужен (WSLg на Windows 11; на Windows 10 нужен сторонний X-сервер) |
| конец расчёта | процесс завершается | окно ждёт, выход клавишей `/` |
| признак успеха | `>>> ASTRA normal exit >>>` печатает сам расчёт | `exe/Build` печатает `ASTRA normal exit` **всегда**, даже после аварии (`exe/Build`, строка 121) |
| CDF | пишется | пишется (снимки JSON идут в обоих режимах) |
| SLURM | **если в `PATH` есть `sbatch`, расчёт уходит в очередь** (`exe/Build`, строки 85–106) | нет |

Ловушка SLURM: на кластере или на машине, где установлен клиент SLURM, `-batch` не считает локально, а печатает `sbatch …/exe/batch.sh` и сразу возвращается. На машине лаборатории это не грозит, если SLURM не установлен. Проверка: `command -v sbatch`.

### 2.4. Окно по времени и шаг

- `-s`/`-e` задают модельное время в секундах **разряда**. Время должно попадать в диапазон данных U-файлов; за его пределами ASTRA экстраполирует или берёт крайние значения. Это тихая ошибка, а не авария.
- Шаг по времени ограничен `TAUMIN`/`TAUMAX`. Задаются они в `equ/log/<модель>` или прямо в модели. **Строка в модели перекрывает log**: в `flux_feqis` стоит `TAUMIN=0.05; TAUMAX=0.05;` (строки 11–12), поэтому шаг 50 мс, хотя в log записано `TAUMAX = 1.0E-03`.
- Снимки для CDF пишутся раз в `DPOUT` секунд модельного времени (`src/astra/astra_main.F90`, строки 122–125), но не чаще шага. В `equ/log/flux_feqis` `DPOUT = 0.2`, поэтому окно 4–5 с даёт 6 срезов: 4.0, 4.2, …, 5.0.
- Для Глобус-М2 разряд длится ~0.1–0.3 с, поэтому значения от AUG (`TAU` 50 мс, `DPOUT` 0.2 с) не годятся. В синтетическом примере §6.4 взяты шаг 5 мс и `DPOUT = 0.01`.

### 2.5. Параллельные расчёты

В одном рабочем каталоге **нельзя** запускать два расчёта одновременно: общие `tmp/astra.nml`, `src/tmp/*.f90`, `obj/`, `bin/`, а одинаковые имена эксперимента и модели означают ещё и общие файлы в `ncdf_out/`. В A7 была та же проблема с файлом post-view (`docu/section5.tex`, строки 2920–2929).

Проверенный обходной путь — отдельная копия рабочего каталога на каждый поток расчётов:

```bash
rsync -a --exclude .git --exclude ncdf_out ~/astra/a8/ /tmp/a8doc/
cd /tmp/a8doc
export ASTRA_PLATFORM=ubuntu
exe/as_exe -m flux_feqis -v aug34954 -s 4 -e 5 -batch
```

Копия весит ~230 МБ и работает, потому что путь к внешним библиотекам `ASTRA_EXT` в `platform/env.ubuntu` абсолютный. `AWD` при запуске `exe/as_exe` из копии берётся из текущего каталога, поэтому `astra8` здесь не годится: он жёстко указывает на `~/astra/a8`.

## 3. Анатомия рабочего каталога

Рабочий каталог `AWD` — это `~/astra/a8`. Файлы, с которыми работает пользователь:

| путь | что лежит | кто пишет | трогать? |
|---|---|---|---|
| `equ/<модель>` | модель: уравнения, источники, вывод | пользователь | да, основной объект работы |
| `equ/log/<модель>` | стартовые значения констант и управляющих параметров (`DPOUT`, `TAUMIN`, `CF*`, `CV*`, геометрия по умолчанию) | пользователь или клавиша `I` в GUI | да; **файл обязателен** |
| `exp/<эксп>` | файл эксперимента: скаляры и ссылки на U-файлы | пользователь | да |
| `exp/nml/<эксп>` или `exp/nml/<машина>` | namelist модулей (равновесие, NBI, …) | пользователь | по необходимости |
| `exp/cnf/`, `exp/nbi/`, `exp/icrh/` | описание машины, геометрия пучков и т. п. | пользователь | для новой машины |
| `udb/<разряд>/` | U-файлы с данными разряда | пользователь или скрипты подготовки | да; исходные данные не править, а перегенерировать |
| `ncdf_out/` | результаты: `*.json` (снимки) и `*.CDF` | расчёт | читать |
| `dat/` | текстовые и PostScript-выгрузки из GUI (клавиши `F`, `G`, `Q`) | GUI | читать |
| `tmp/astra.nml` | параметры последнего запуска | `as_exe` | нет (можно читать) |
| `src/tmp/` | Фортран, сгенерированный из модели, и `model.txt` | `pyparse` | нет; полезно читать при ошибках |
| `obj/`, `mod/`, `lib/`, `bin/` | объектные файлы, модули, библиотеки, исполняемые файлы | `make` | нет |
| `src/`, `pyparse/`, `exe/` | исходники ядра, парсер, скрипты запуска | разработчики | нет |
| `fnc/`, `fml/`, `sbr/` | библиотека функций, формул, подпрограмм для моделей | разработчики и пользователи | добавлять своё можно, см. [09](09-user-area-catalog.md) |
| `regressions/` | эталонные CDF с кластера IPP | разработчики | нет |
| `docu/` | исходники руководства (LaTeX) | — | читать |

Подробнее о каталогах, появляющихся при сборке, — [02 §7](02-build-and-run.md#7-каталоги-и-файлы-которые-появляются-при-работе).

Почему `equ/log/<модель>` обязателен: `src/astra/read_input.f90` (строки 93–103) открывает его безусловно и при отсутствии делает `ERROR STOP`. Новый log проще всего получить копией от похожей модели (§4.1) или клавишей `I` в GUI.

Namelist ищется сначала как `exp/nml/<эксп>`, затем как `exp/nml/<машина>` (`read_nml`, `src/astra/read_input.f90`, строка 146). Если нет ни того ни другого, расчёт `flux_feqis` **всё равно идёт** (проверено в §4): RABBIT и NBI в нашей сборке выключены, а FEQIS с фиксированной границей берёт значения `equil_settings` по умолчанию. Для модели с NBI или свободной границей namelist нужен.

Имена результатов строятся склейкой без разделителя: эксперимент `my34954` и модель `my_feqis` дают `ncdf_out/my34954my_feqis.CDF` и снимки `my34954my_feqis-1.json`, `-2.json`, … Новый расчёт с теми же именами **перезаписывает** CDF.

## 4. Учебный пример: поменять параметр и сравнить результат

Задача: взять тестовую пару «модель + эксперимент», заменить концентрацию примеси углерода на фиксированные 2 % от `NE`, посчитать и сравнить с исходным расчётом в Python. Всё проверено 2026-10-01 в копии `/tmp/a8doc`.

### 4.1. Скопировать модель, её log и эксперимент

```bash
cd /tmp/a8doc                        # копия AWD, см. §2.5
cp equ/flux_feqis      equ/my_feqis
cp equ/log/flux_feqis  equ/log/my_feqis     # без него ERROR STOP
cp exp/aug34954        exp/my34954
```

`exp/nml/aug34954` в этом примере не копировался: расчёт прошёл и без него (§3). U-файлы не копируются: `exp/my34954` ссылается на те же `udb/34954/…`.

### 4.2. Поменять параметр

В `equ/my_feqis` найдите строку с примесью и замените её:

```text
было:   NIZ1=CIMP1*NE;
стало:  NIZ1=0.02*NE;   ! 2% carbon
```

`NIZ1` — плотность первой примеси, `CIMP1` — константа модели. Синтаксис (`;` в конце, `!` для комментария) — [03](03-model-language.md). Эффективный заряд `ZEF` модель считает из плотностей примесей, поэтому изменится и он, а через сопротивление плазмы — напряжение на обходе `UPL`.

### 4.3. Запустить

```bash
cd /tmp/a8doc
export ASTRA_PLATFORM=ubuntu
exe/as_exe -m my_feqis -v my34954 -s 4 -e 5 -batch 2>&1 | tee /tmp/my_run.log
```

Ожидаемый вывод (сокращён; на нашей машине 27 с, из них сборка несколько секунд):

```text
as_parse | WARNING: X array PRADX used in equ, but missing in exp
...
Running /tmp/a8doc/bin/my_feqis_batch.exe without graphic interactive window
 Reading u-file udb/34954/MAG34954.IPL_AVG
 ...
   Written file /tmp/a8doc/ncdf_out/my34954my_feqis-1.json
 ...
>>> ASTRA normal exit >>>
    Total time steps        21
    Average time step   50.000 msec
    Equilibrium                     ...    98.8%
... | json2cdf | INFO: Stored /tmp/a8doc/ncdf_out/my34954my_feqis.CDF
```

Как читать вывод:

- `WARNING: X array PRADX used in equ, but missing in exp`: модель ссылается на экспериментальный профиль излучения `PRADX`, а в эксперименте его нет; профиль будет нулевым. Для теста это нормально, для настоящего расчёта такие предупреждения нужно разбирать.
- `Reading u-file …`: какие файлы данных реально прочитаны. Строка `not found, skipping` здесь означает ошибку в пути.
- `Equilibrium … 98.8%`: почти всё время уходит на расчёт равновесия FEQIS. Ускорять перенос бессмысленно, время решает частота пересчёта равновесия.
- Последняя строка `json2cdf … Stored`: CDF создан.

Проверка успеха одной командой:

```bash
grep -q '>>> ASTRA normal exit >>>' /tmp/my_run.log && ls -l ncdf_out/my34954my_feqis.CDF
```

### 4.4. Где результат

`ncdf_out/my34954my_feqis.CDF` — NetCDF classic, ~7 МБ. В нём около 1137 переменных: все массивы ядра (профили по ρ, скаляры по времени, двумерное равновесие). Размерности тестового расчёта: `TIME` = 6, `XRHO` = 91, `RHO_SURF` = 91, `THETA` = 90, `R` = 65, `Z` = 65.

Быстрый просмотр без Python, если установлены утилиты NetCDF:

```bash
ncdump -h ncdf_out/my34954my_feqis.CDF | less
```

Формат и происхождение переменных — [08 §8](08-graphics-and-output.md#8-формат-cdf). Значение физических имён — [10 §5](10-tokamak-usage.md) и [glossary.md](glossary.md).

### 4.5. Прочитать в Python

Нужны `numpy` и `scipy` (на нашей машине scipy 1.11.4). Скрипт запускается из `ncdf_out/` и сравнивает исходный и изменённый расчёты:

```python
import numpy as np
from scipy.io import netcdf_file

def load(path, names):
    with netcdf_file(path, 'r', mmap=False) as f:
        out = {'TIME': f.variables['TIME'].data.copy(),
               'XRHO': f.variables['XRHO'].data.copy()}
        for n in names:
            v = f.variables[n]
            out[n] = v.data.copy()
            out[n + ':units'] = v.units.decode()
        return out

names = ['TE', 'NE', 'ZEF', 'UPL', 'MU', 'IPL', 'li3']
ref = load('aug34954flux_feqis.CDF', names)
new = load('my34954my_feqis.CDF', names)
print('time slices:', ref['TIME'])
it = -1
for n in ['ZEF', 'UPL']:
    print(f"{n} on axis [{ref[n+':units']}]: ref={ref[n][it,0]:.3f}  new={new[n][it,0]:.3f}")
print('q0 = 1/MU(0):', 1/ref['MU'][it,0], 1/new['MU'][it,0])
print('li3:', ref['li3'][it], new['li3'][it])
```

Фактический вывод:

```text
time slices: [4.  4.2 4.4 4.6 4.8 5. ]
ZEF on axis []: ref=1.000  new=1.600
UPL on axis [V]: ref=0.158  new=0.237
q0 = 1/MU(0): 0.5516 0.5285
li3: 0.909 0.942
```

Проверка на здравый смысл: `ZEF` вырос с 1.0 до 1.6, сопротивление плазмы пропорционально `ZEF`, и напряжение на обходе выросло примерно в той же пропорции (0.158 → 0.237 В). Модель отреагировала так, как ожидает физик.

Что важно знать про чтение:

- `mmap=False` и `.copy()` обязательны, иначе после закрытия файла массивы станут недействительными.
- Атрибуты `units` и `long_name` в scipy приходят как `bytes`, их нужно `.decode()`.
- Профили имеют форму `(TIME, XRHO)`, скаляры — `(TIME,)`. Индекс `[it, 0]` — значение на магнитной оси, `[it, -1]` — на границе.
- `XRHO` — нормированный радиус ρ/ρ_max от 0 до 1 (в ASTRA ρ_max называется `ROC`).
- Запас устойчивости `q` хранится как `MU = 1/q`, поэтому `q0 = 1/MU[:, 0]`.
- Можно читать и через `netCDF4` или `xarray`, если они установлены. Пример выше использует только scipy, чтобы не тянуть лишних зависимостей.

### 4.6. Построить график

```python
import matplotlib
matplotlib.use('Agg')                     # без окна; файл PNG
import matplotlib.pyplot as plt
from scipy.io import netcdf_file
```

### 4.7. Как сохранить в CDF свою величину

В CDF попадают **только массивы ядра**. Выражения из секций вывода модели (то, что рисуется в окне, например `HEXP` или отношение `NEC/NEAVB`) **не сохраняются**. Если нужна производная величина, присвойте её зарезервированному массиву или скаляру в теле модели:

```text
CAR1=QETOT;            ! профиль: полный электронный тепловой поток
CF8=NEC/NEAVB;         ! скаляр: пикированность плотности
```

`CAR1`…`CARnn` — свободные профили, `CF1`…`CFnn` — свободные скаляры. Потом они читаются из CDF под этими именами. Проверьте, что выбранный номер не занят в самой модели: в `flux_feqis` уже используется `CAR2 = QITOT` (строка 65), а `CAR2X` — профиль `q` из эксперимента. Список занятых имён можно получить так: `grep -n "CAR[0-9]\|CF[0-9]" equ/<модель>`.

## 6. Новый эксперимент для разряда Глобус-М2 (рекомендация)

> Это **рекомендация**, а не проверенная процедура лаборатории. Настоящих данных Глобус-М2 в формате A8 у нас пока нет (2026-10-01). Проверено только то, что синтетический эксперимент с геометрией Глобус-М2 разбирается и считается (§6.4). Правила формата — [04 §14](04-experiment-data.md#14-рекомендации-для-новой-установки-глобус-м2), здесь только порядок действий.

### 6.1. Какие данные собрать

Для интерпретирующего расчёта (как `flux_feqis`) нужны, по убыванию важности:

| величина | имя в ASTRA | источник на Глобус-М2 (предположение) | единицы в exp-файле после множителя |
|---|---|---|---|
| ток плазмы | `IPL` | магнитные измерения | МА |
| тороидальное поле | `BTOR` | ток катушек тороидального поля | Тл |
| граница плазмы | `NAMEXP BNDU` (пара U-файлов `_r`, `_z`) | EFIT или метод токовых нитей, позже pyGSS | м |
| `Te(ρ)`, `ne(ρ)` | `TE`, `NE` | томсоновское рассеяние | кэВ, 10¹⁹ м⁻³ |
| `Ti(ρ)` | `TI` | CXRS/NPA | кэВ |
| `Zeff` | `ZEF` или скаляр `ZRDnX` | оценка или спектроскопия | — |
| излучение | `PRAD` | болометрия | МВт/м³ |
| профиль `q` | `CAR2` в случае `flux_feqis` | EFIT | — |
| мощность и профили нагрева пучком | `QNBI`, `PEX`, `PIX`, `CUX` | паспорт NBI; профили — расчёт NUBEAM вне ASTRA | МВт; МВт/м³; МА/м² |

Зачем каждая величина нужна физически — [10 §4](10-tokamak-usage.md). NUBEAM в ASTRA 8 не входит, поэтому его профили подаются как внешние источники `PEX`/`PIX`, а не вычисляются моделью.

### 6.2. Шаги

1. **Выбрать имена.** Эксперимент `exp/gm2_<разряд>`, U-файлы в `udb/<разряд>/`. Номер разряда — пять цифр: формат U-файла хранит номер в поле `i7`, а `pyparse/ufiles.py` пишет и разбирает имена файлов вида `<префикс><номер5>.<расширение>`.
2. **Сгенерировать U-файлы** из исходных данных скриптом. Исходные `.SHT`/`.DAT` не трогать. Для записи есть класс `UFILE` в `pyparse/ufiles.py` (пример в §6.3).
3. **Написать `exp/gm2_<разряд>`** по образцу `exp/aug34954` с геометрией Глобус-М2 (§6.4). Обязательно указать `ABC` (начальный малый радиус плазмы): иначе он наследуется из log модели AUG (0.5 м), и расчёт падает с `ABC cannot exceed AB`.
4. **Выбрать модель.** Начать с копии `flux_feqis` (`IPEQL=5`, FEQIS с фиксированной границей) под новым именем вместе с `equ/log/…`. В копии поменять шаг `TAUMIN`/`TAUMAX` (в модели), `DPOUT` (в log) и убрать то, чего нет в данных. Ориентир по масштабу шага — 1–5 мс.
5. **Короткий batch-расчёт** на окне в несколько десятков миллисекунд. Проверить вывод: все `Reading u-file` нашли файлы, нет `not found, skipping`, `Unrecognized`, `Warning: AWALL`, понятны все `WARNING: X array … missing in exp`.
6. **Проверить результат в CDF** (§4.5): `IPL`, `BTOR`, `ELONG`, `TRIAN` совпадают с заданными; профили `TEX`, `NEX` ненулевые и правильного масштаба; `q` на границе разумен.
7. **Только потом** включать предсказательные уравнения (`TE:EQ;` и т. п.), источники пучка и сравнение с измерениями.

После изменения файла эксперимента без изменения модели принудительно пересоберите модель: `touch equ/<модель>`. Файл эксперимента не входит в зависимости `make` ([04 §14.5](04-experiment-data.md#145-порядок-проверки-нового-файла)).

### 6.3. Запись U-файла из Python

Проверено 2026-10-01: файлы записываются и читаются обратно тем же классом, а ASTRA их принимает (§6.4).

```python
import sys
import numpy as np
sys.path.insert(0, '/home/<user>/astra/a8/pyparse')   # ufiles.py и rw_for.py
from ufiles import UFILE

shot = 42155
udir = '/home/<user>/astra/a8/udb/%d' % shot
t = np.linspace(0.12, 0.20, 9)                 # с
rho = np.linspace(0, 1, 21)                    # нормированный rho_tor

u = UFILE()                                    # 1D: величина от времени
u.shot, u.pre, u.ext = shot, 'MAG', 'IPL'      # -> MAG42155.IPL
u.X = {'name': 'Time', 'unit': 'Seconds', 'data': t}
u.f = {'name': 'Plasma Current', 'unit': 'MA', 'data': ip_MA}
u.write(udir=udir, dev='GLBM')

u2 = UFILE()                                   # 2D: профиль от времени и rho
u2.shot, u2.pre, u2.ext = shot, 'TS', 'TE'     # -> TS42155.TE
u2.X = {'name': 'Time', 'unit': 'Seconds', 'data': t}
u2.Y = {'name': 'rho_tor', 'unit': '', 'data': rho}
u2.f = {'name': 'TE', 'unit': 'eV', 'data': te_eV}   # форма (len(t), len(rho))
u2.write(udir=udir, dev='GLBM')

back = UFILE(udir + '/TS%05d.TE' % shot)       # чтение обратно
print(back.f['data'].shape)
```

Замечания:

- `dev='GLBM'` — четырёхбуквенный код машины в первой строке U-файла. Для AUG там стоит `AUGD`. ASTRA этот код не проверяет, он нужен для людей и других программ.
- Массив двумерного U-файла имеет форму `(время, радиус)`.
- Имя граничного файла `UFILE.write` строит как `<pre><shot>.<ext>`. Для границы ASTRA ждёт пару `<разряд>.bnd.txt_r` / `_z` (по образцу `udb/34954/`), поэтому после записи файлы нужно переименовать (см. скрипт ниже) или записать вручную.
- Множитель после двоеточия в exp-файле переводит единицы файла в единицы ASTRA: эВ → кэВ — `1.e-3`; для `NE` в образце AUG стоит `1.e-13`. Единицы U-файла и множитель должны соответствовать друг другу, подробнее — [04 §7.3](04-experiment-data.md#73-единицы).

### 6.4. Проверенный синтетический пример

Чтобы проверить сам формат для геометрии сферического токамака, 2026-10-01 в `/tmp/a8doc` собран эксперимент с **выдуманными** профилями и номером разряда 90001: R = 0.36 м, a = 0.22 м, κ = 1.9, δ = 0.3, `IPL` = 0.35 МА, `BTOR` = 0.8 Тл. Это не данные Глобус-М2, а проверка того, что цепочка работает.

Генерация U-файлов (сокращённо; полный скрипт строит также `NE`, `TI`, `VTOR`, `QPR` тем же способом):

```python
th = np.linspace(0, 2*np.pi, 180, endpoint=False)
R0, a, kap, dlt = 0.36, 0.22, 1.9, 0.3
r = R0 + a*np.cos(th + np.arcsin(dlt)*np.sin(th))      # граница с треугольностью
z = kap*a*np.sin(th)
pos = np.arange(1, 181, dtype=float)
for comp, val in (('r', r), ('z', z)):
    u = UFILE()
    u.shot, u.pre, u.ext = shot, '%d.bnd' % shot, 'txt_' + comp
    u.X = {'name': 'Time', 'unit': 'Seconds', 'data': t}
    u.Y = {'name': 'POSITION', 'unit': '', 'data': pos}
    u.f = {'name': comp.upper() + ' BOUNDARY', 'unit': 'M',
           'data': np.outer(np.ones_like(t), val)}
    u.write(udir=udir, dev='GLBM')
# затем: mv 90001.bnd90001.txt_r 90001.bnd.txt_r (и _z)
```

### 7.2. Известные несовместимости

Источники: `docu/addendum_A8.tex`, [04 §9](04-experiment-data.md#9-отличия-a8-от-a7-и-почему-не-работает-expreadme), опыт установщика (`../../installer/docs/DETAILED.md`).

**Модель (`equ/`)**:

1. Функции из `fnc/` вызываются только как массивы или как граничные интегралы. Значение в точке пишется как `TE(AFX(x))`.
2. Граничное условие автоматически берётся из начального, если не задано явно.
3. Формула из `fml/` и `GRAD` не могут стоять на одной строке.
4. Набор значений `IPEQL` другой: −2, −1, −6, 0, 1, 4 (SPIDER), 5 (FEQIS). Свободная граница SPIDER удалена ([06](06-equilibrium.md)).
5. Подпрограммы A7, которых нет в `sbr/` A8, придётся переносить вручную ([09](09-user-area-catalog.md)). NUBEAM ни в A7, ни в A8 не является частью ASTRA, связка с ним внешняя.

**Эксперимент (`exp/`, `udb/`)**:

1. Исходный разборщик U-строк A8 падает на строках A7 с табуляцией и комментариями `****`. Наш установщик ставит патч в `pyparse/exp_parser.py::parse_u_line` ([DETAILED.md](../../installer/docs/DETAILED.md), раздел 3).
2. Даже после патча `exp/readme` из A7 падает с `AssertionError` в `parse_exp2d`, а `equ/showdata` ссылается на отсутствующие `udb/00000.tes`/`00000.tis`. Разбор — [04 §9.2](04-experiment-data.md#92-разбор-expreadme-по-шагам).
3. Скалярная секция в фиксированном формате A7 читается, свободный `NAMEXP` — расширение A8 ([04 §3](04-experiment-data.md#3-скалярная-секция)).
4. Сами U-файлы — общий формат TRANSP, он не менялся.

**Результаты**: файлы post-view A7 (`.res/`) A8 не читает. Если старые результаты нужны для сравнения, их придётся выгрузить в текст средствами A7 (`Review`, запись в `dat/`) до отказа от A7.

### 7.3. Порядок переноса одной пары «модель + данные»

Рекомендация, не проверено на реальных файлах лаборатории (их у нас нет, 2026-10-01):

1. Скопировать модель, её log (если есть) и эксперимент из A7 в **копию** AWD A8, U-файлы — в `udb/`.
2. Если log нет, взять `equ/log/flux_feqis`, переименовать и поправить геометрию; либо запустить один раз GUI и сохранить log клавишей `I`.
3. Запустить короткий batch (§6.2, шаг 5). Ошибки разбора видны **до** компиляции, в строках `as_parse | …` и Python-трассировках `pyparse`.
4. Исправить модель по списку §7.2. Сгенерированный Фортран и `src/tmp/model.txt` показывают, как парсер понял модель.
5. Сравнить результат A8 с выгрузкой A7 на тех же входах по нескольким контрольным величинам (`UPL`, `q0`, `li3`, `WTOT`). Расхождение на уровне процентов может быть нормой: решатели и равновесие в A8 другие.
6. Записать найденные несовместимости: они понадобятся для следующих моделей.

| код возврата 0, а CDF нет или он старый | `as_exe` всегда возвращает 0 | проверять `>>> ASTRA normal exit >>>` и время изменения CDF (§1) |
| GUI-режим пишет `ASTRA normal exit`, но расчёт явно упал | в GUI эту строку печатает `exe/Build` безусловно | смотреть вывод выше, `ERROR STOP`, backtrace |
| `ERROR STOP` сразу после запуска, без строк `Reading u-file` | нет `equ/log/<модель>` | скопировать log от похожей модели (§4.1) |
| `>>> Error: ABC cannot exceed AB. Check your file exp/…` | `ABC` унаследован из log другой машины | задать `ABC` в эксперименте (§6.2, шаг 3) |
| `Warning: AWALL …` | `AWALL` не согласован с `AB`/`RTOR` | поправить геометрию в exp ([04 §14.2](04-experiment-data.md#142-геометрия-сферического-токамака)) |
| `… not found, skipping` | неверный путь к U-файлу (путь от `udb/`) | проверить имя и регистр: Linux различает `IPL` и `ipl` |
| `as_parse \| WARNING: X array … used in equ, but missing in exp` | модель использует профиль данных, которого нет в эксперименте; он будет нулевым | добавить данные или убрать из модели |
| Python-трассировка в `parse_u_line` или `parse_exp2d` | файл эксперимента в формате A7 | патч установщика; см. §7.2 |
| `astra8 -batch` мгновенно вернулся с `sbatch …` | на машине есть SLURM | считать в окружении без `sbatch` в `PATH` или ждать задачу в очереди |
| `astra8` без ключей открыл окно | `-batch` не запоминается | добавить `-batch` |
| посчитал не ту модель или не тот эксперимент | недостающие ключи взяты из `tmp/astra.nml` | всегда указывать `-m -v -s -e` явно |
| в CDF всего 1–2 среза | шаг (`TAUMIN`/`TAUMAX` в модели) или `DPOUT` (в log) крупнее окна | уменьшить шаг и `DPOUT` (§2.4) |
| поменял exp, а результат прежний | exp не входит в зависимости `make` | `touch equ/<модель>` |
| нужной величины нет в CDF | выражения вывода не сохраняются | присвоить `CARn`/`CFn` (§4.7) |
| два расчёта портят друг друга | общий AWD | отдельные копии (§2.5) |
| окно не открывается (`cannot open display`) | нет X-сервера; Windows 10 без WSLg | batch, или Windows 11 + WSLg, или сторонний X-сервер |
| окно не закрывается по `Esc` | в A8 выход — `/` | нажать `/` |
| расчёт идёт минутами на 1 с | почти всё время — равновесие FEQIS | это нормально; уменьшить окно, реже пересчитывать равновесие ([06](06-equilibrium.md)) |
| `Error in find new boundary` на последнем шаге | известное поведение на регрессии `fbe`/`AUG33040_2500`, есть и в эталоне IPP | не баг установки |
| цифры отличаются от эталона `regressions/` на 0.1–3 % | gfortran против Intel на кластере IPP | норма; допуск `compareRegressions.py` 1e-7 для gfortran не проходит |

## 9. Вопросы инженера (FAQ)

**Можно ли запускать ASTRA как библиотеку из Python?**
Нет. ASTRA — программа, которая перекомпилируется под каждую модель и общается через файлы. Из Python её можно вызвать через `subprocess`: подготовить exp и U-файлы, запустить `exe/as_exe … -batch` в отдельной копии AWD, проверить признак успеха и прочитать CDF. Именно так устроены внешние связки, например ASTRA + NUBEAM у Глобус-М2 ([10 §8](10-tokamak-usage.md)).

**Как перебрать параметр (scan)?**
Константы удобнее всего вынести в `equ/log/<модель>` или в саму модель, генерировать варианты скриптом и запускать каждый в своей копии AWD (§2.5). На 24-ядерной машине копии можно гонять параллельно. Внутри одного расчёта ASTRA использует OpenMP; установщик ставит `OPENBLAS_NUM_THREADS=1`, чтобы не было переподписки ([DETAILED.md](../../installer/docs/DETAILED.md)).

**Сколько места и времени занимает расчёт?**
Тестовый `flux_feqis` — ~30 с на 1 с модельного времени при шаге 50 мс и ~7 МБ CDF на 6 срезов. Размер CDF растёт с числом срезов (каждый JSON-снимок — полный набор массивов). Время почти целиком определяет равновесие.

**Можно ли удалить `*.json` в `ncdf_out/`?**
Да, после успешной сборки CDF они не нужны: это промежуточные снимки, `json2cdf` строит из них CDF. Но удаляйте их только после проверки CDF.

**Нужен ли интернет или доступ в IPP для работы?**
Для обычных расчётов нет. Доступ к GitLab MPCDF нужен для обновления исходников и для закрытых внешних модулей (RABBIT, TORBEAM и др.), которые в нашей сборке выключены ([07](07-heating-and-external-modules.md)).

**Чем A8 лучше A7 для лаборатории?**
Результат сразу в NetCDF и читается любым инструментом. Расчёт идёт в batch без окна и скриптуется. Сборка воспроизводимая (установщик, Docker-образ). Подробнее о последствиях переноса — [10 §8](10-tokamak-usage.md).

**Как понять, что означает переменная в CDF?**
Атрибуты `long_name` и `units` (§4.5), затем [glossary.md](glossary.md), затем объявление в `src/astra/` (поиск по имени). Для имён, общих с A7, работает `docu/section12.tex`.

**Какой номер разряда указывать, если у Глобус-М2 номера шестизначные?**
Не проверено. Сейчас номера разрядов Глобус-М2 пятизначные (порядка 4xxxx), и `ufiles.py` форматирует номер как `%05d`. При переходе на шесть цифр формат первой строки (`i7`) это допускает, а имена файлов придётся проверить отдельно.

**Где хранить свои модели?**
Не в рабочей копии MPCDF под git, а в отдельном каталоге или репозитории. Копировать в `equ/` перед запуском, результаты забирать из `ncdf_out/`. Так обновление ASTRA не затрёт модели лаборатории.

**Можно ли запускать на Windows без WSL?**
Нет. Сборка и запуск рассчитаны на Linux. На Windows работает WSL2 (окно через WSLg на Windows 11) или Docker-образ `astra8`.
