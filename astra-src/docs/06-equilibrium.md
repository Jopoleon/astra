# 06. Равновесие в ASTRA 8: IPEQL, FEQIS, свободная граница, VMEC

## О чём глава

Глава описывает, как ASTRA 8 получает метрику магнитных поверхностей, нужную транспортным уравнениям: какие решатели равновесия есть в коде, чем они управляются (`IPEQL`, `NEQUIL`, `MEQUIL`, `DTEQL`, `ITFBE` и др.), как устроен встроенный решатель FEQIS (фиксированная и свободная граница, катушки, вакуумная камера, матрицы Грина), откуда берётся граница плазмы, как подключается VMEC для стеллараторов, и какие ошибки встречаются на практике. Отдельный раздел даёт рекомендации по настройке FEQIS для сферического токамака Глобус-М2.

Все утверждения привязаны к исходникам в `astra-src` (MPCDF `67281112`, состояние на 2026-10-01). Пути указаны относительно корня `astra-src`. Где поведение не проверено запуском, это сказано явно.

## 1. Уравнение равновесия и связь с транспортом

### 1.1. Уравнение Грэда–Шафранова

Для осесимметричного токамака равновесие задаётся уравнением Грэда–Шафранова для полоидального потока ψ(R, z):

\[
R\,\frac{\partial}{\partial R}\frac{1}{R}\frac{\partial\psi}{\partial R} + \frac{\partial^2\psi}{\partial z^2}
= -\mu_0 R^2\,\frac{dp}{d\psi} - F\frac{dF}{d\psi},
\]

где \(F = R B_\varphi\). В документации ASTRA оно выписано в `docu/section3.tex` (около строк 454–520) вместе с выражением для продольной плотности тока через \(p'\) и \(FF'\). Правая часть в коде собирается подпрограммами `RHSEQ` и `RHSEQ2` в `src/astra/metrics.f90` (строки 1488 и 1550): из транспортных профилей вычисляются `EQPF` (\(p'\)), `EQFF` (\(FF'\)) и тороидальный ток `CUTOR` в МА/м².

### 1.2. Почему транспорту нужна метрика

ASTRA решает 1.5D-задачу: транспортные уравнения записаны в координате ρ = \(\sqrt{\Phi/(\pi B_0)}\) (тороидальный поток), а вся 2D-геометрия входит через усреднённые по поверхности метрические коэффициенты. Решатель равновесия обязан заполнить их на транспортной сетке:

| Величина | Смысл (кратко) |
|---|---|
| `G11`, `G22`, `G33` | метрические коэффициенты ⟨\|∇ρ\|²⟩-типа, входящие в диффузионные операторы и уравнение для тока |
| `VR`, `VRS` | \(dV/d\rho\) на основной и смещённой сетке |
| `SLAT` | площадь поверхности |
| `DRODA`, `GRADRO` | \(d\rho/da\), ⟨\|∇ρ\|⟩ |
| `IPOL` | нормированная полоидальная функция тока \(F/(R_0B_0)\) |
| `BDB02`, `B0DB2`, `BMAXT`, `BMINT`, `FOFB` | усреднения по \(B\) (для бутстрэпа, захваченных частиц и т. п.) |
| `SHIF`, `ELON`, `TRIA`, `SHIV`, `SQUARN` | шафрановский сдвиг, вытянутость, треугольность, вертикальный сдвиг, «квадратность» поверхностей |
| `ROC` | граничное значение ρ (\(\rho_B\)) |

Полный список переменных и их описания есть в `astra_variables.json`; подробнее о сетке и метрике в транспортном решателе — в [05-solver-core.md](05-solver-core.md).

### 1.3. Цикл «транспорт ↔ равновесие»

Связь итерационная (`docu/section3.tex`, раздел о замыкании системы, строки ~1230–1345; `docu/section4.tex`, «Link between transport and equilibrium», строки ~785–944):

1. Транспорт делает шаг с текущей метрикой и даёт новые \(p(\rho)\) и \(\psi(\rho)\) (или \(q\)/ток).
2. Решатель равновесия по \(p'\), \(FF'\) (или по \(p\) и \(q\)) и границе пересчитывает поверхности и метрику.
3. Метрика возвращается в транспорт.

В `src/astra/stepup.F90` вызов `METRIC` стоит внутри цикла `tr_eq_loop`: число внутренних итераций транспорт–равновесие ограничено `NITREQ`, критерий сходимости — `ATREQ` (по умолчанию `1e-4`, `src/astra/scalars.f90` около строки 202), флаг завершения — `IFTREQ`. Пересчёт равновесия разрежается по времени: в каждой ветке `METRIC` стоит условие `TIME-TIMEQL >= NDTEQUILMY*DTEQL`, то есть при `DTEQL = 0` (по умолчанию) равновесие считается на каждом шаге.

Для свободной границы связь усложняется: ψ на границе определяется внешними токами, а объём и \(\Phi_b\) подбираются согласованно. Схема описана в `docu/coupling_with_2d_equil_add_EF.tex` (вводятся \(H = d\psi/dV\), \(y = H^2/2\), ОДУ для \(y\), подбор \(\Phi_b\) по объёму, внешняя и внутренняя итерации с нижней релаксацией 0.5) и реализована в `src/astra/gs_solver.F90` (раздел 4).

## 2. Выбор решателя: IPEQL и сопутствующие переменные

### 2.1. Значения IPEQL

Диспетчер — `METRIC()` в `src/astra/metrics.f90`, `SELECT CASE(IPEQL)` на строках 118–215. Значение по умолчанию: **`IPEQL = 5` (FEQIS)**, `src/astra/scalars.f90` строка 155 (комментарий «4- SPIDER, 5- FEQIS»).

| IPEQL | Что делает `METRIC` | Источник в коде |
|---|---|---|
| −2 | цилиндр без тороидальности: `EQCYL` + `RHSEQ` | `metrics.f90` стр. 120, `EQCYL` стр. 256 |
| −1 | метрика из exp-файла (X-массивы `SHX`, `ELX`, `TRX`, `G33X`, `IPOLX`, `VRX`, `SLATX`, `G11X`, `G22X`, `DRODAX`, `SHIVX`, `SQUAX`): `ROC3A` + `set_external_metric` + `RHSEQ` | стр. 124, `set_external_metric` стр. 488 |
| −6, 6 | метрика из файла `input_metric.dat` через `set_external_metric_2` → `extmetric_input` (6 — стеллараторный вариант) | стр. 130, 136, 665, 680 |
| 0 | нет решателя: аналитическая оценка `EQGUESS` (через `SETGEO`) | стр. 142, `EQGUESS` стр. 343, `SETGEO` стр. 1851 |
| 1 | 3-моментный решатель EMEQ: `A2EMEQ` (`src/astra/emeq.f90`) | стр. 145, `A2EMEQ` стр. 844 |
| 2 | **ветки нет**: метрика не пересчитывается | — |
| 3 | только `RHSEQ` (комментарий «equil iterations»), метрика не пересчитывается | стр. 161 |
| 4 | SPIDER (`equil_solver = 3`) через `RHSEQ2` + `A2GSSOLVER` | стр. 169 |
| 5 | FEQIS (`equil_solver = 101`) через `RHSEQ2` + `A2GSSOLVER` | стр. 169 |
| 7 | VMEC (стелларатор / токамак через VMEC): `vmec_interface` | стр. 183 |
| 9 | **ветки в `METRIC` нет**; значение используется только в стеллараторных ветках `CUOFMU`/`CUOFP`/`FPMUOFCU` | `metrics.f90` стр. 1607–1798 |

Значения из `astra_variables.json` (строки 455–476): «0 doesnt do anything, 1 forces 3mom, 4 spider, 5 feqis». В `docu/addendum_A8.tex` (строки ~588–668) IPEQL = 2 и 3 помечены «not used», а SPIDER со свободной границей объявлен недоступным.

Важные следствия:

- **SPIDER (IPEQL = 4) — закрытый код IPP.** В `src/astra/gs_solver.F90` вызов `spider_run` и чтение параметров SPIDER обёрнуты в `#ifdef SPIDER`. Без этого макроса `A_EQUIL` при `equil_solver = 3` не вызывает никакого решателя, и `equil_out` остаётся незаполненным (предположительно — мусор или нули; запуском не проверено). Тем не менее модели `equ/flux_spider`, `equ/flux_neo_tglf`, `equ/stelxes`, `equ/astrahl_simple_msp` в `repo_user_area/` всё ещё содержат `IPEQL = 4`. Для открытой сборки их нужно переводить на 5.
- Коммит `e66f6ba1` (G. Tardini, 2026-10-01) перевёл регрессионные модели `flux_cuas`, `flux_neo`, `flux_pel`, `flux_tglf`, `flux_tglf_serial`, `imep_pw04/08`, `qlk`, `qlknn`, `tglf_rot_pred_08` с IPEQL = 4 на 5 и обновил эталонные CDF. То есть основной путь регрессий теперь — FEQIS.
- В начале `METRIC` есть комментарий «if IPEQL = 70, 71, …, 79 … set IPEQL to 7» (стр. 49–50), но кода, который это делает, нет: вариант VMEC выбирается только через `vmec_option`.

### 2.2. Сопутствующие переменные

Значения по умолчанию взяты из `src/astra/scalars.f90` (строки 138–160); описания — из `astra_variables.json` и кода.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NEQUIL` | 0 | число радиальных поверхностей для решателя; для EMEQ берётся `min(NEQUIL, NP)` с `NP = 101` (`src/astra/emeq.f90` стр. 8); для FEQIS/SPIDER — `abs(NEQUIL)` |
| `MEQUIL` | 0 | число полоидальных точек (для SPIDER/FEQIS/VMEC) |
| `DTEQL` | 0 | минимальный интервал между пересчётами равновесия, с |
| `NB2EQL` | 1 | множитель вклада давления быстрых частиц `(PBLON+PBPER)/2` в давление для равновесия (`A2GSSOLVER`) |
| `ITFBE` | `1.e6` | момент включения свободной границы; отрицательное значение — FBE выключена навсегда |
| `ITFBP` | 0 | способ граничного условия для ψ при FBE (см. раздел 8) |
| `ICIRCQ` | 0 | решать ли уравнения цепей катушек при FBE |
| `IPCTRL` | 0 | режим контроллера/рефита токов (фактически влияет только на SPIDER, см. раздел 8) |
| `SGNIP`, `SGNBT` | 1, 1 | знаки тока плазмы и тороидального поля |
| `IFBEY` | счётчик | число шагов, прошедших с включения FBE (ведётся в `stepup.F90`) |
| `IPLFBE`, `PHIEDG` | — | ток плазмы для FBE; тороидальный поток на границе (VMEC) |
| `vmec_option` | 0 | вариант работы VMEC (раздел 12) |
| `ATREQ`, `NITREQ` | `1e-4`, — | точность и число итераций транспорт–равновесие |

**Внимание.** По умолчанию `IPEQL = 5`, но `NEQUIL = 0` и `MEQUIL = 0`. В `A2GSSOLVER` размеры сеток берутся как `abs(NEQUIL)`/`abs(MEQUIL)`, поэтому модель, которая не задаёт `NEQUIL`/`MEQUIL` явно, получит вырожденную сетку FEQIS. Предположительно это приводит к аварии; запуском не проверено. Все рабочие модели (`equ/fbe`, `equ/flux_feqis`, `equ/flux_emeq`) задают `NEQUIL = 91`, `MEQUIL = 90`. Кроме того, процедура графики `src/graph/graph_utils.f90` (около строки 1295) при IPEQL 4/5 и `MEQUIL == 0` обнуляет `SHIF` и `TRIA` и ставит `ELON = 1` перед рисованием.

## 3. Простые режимы

### 3.1. Цилиндр (IPEQL = −2) и аналитическая оценка (IPEQL = 0)

`EQCYL` (`metrics.f90` стр. 256) строит цилиндрическую метрику. `EQGUESS` (стр. 343) использует `SETGEO` (стр. 1851), где профили формы задаются по граничным `ELONG`, `TRIAN`, `SHIFT`:

- \(\kappa(\rho) = \tfrac12\,(1 + \kappa_b + (\kappa_b - 1)\rho_n^2)\);
- \(\delta(\rho) = \delta_b\,\rho_n^2\);
- сдвиг постоянный.

Этот режим годится для отладки транспорта, но не для количественного сравнения с экспериментом.

### 3.2. 3-моментный решатель EMEQ (IPEQL = 1)

`A2EMEQ` (`metrics.f90` стр. 844) вызывает решатель из `src/astra/emeq.f90`. Поверхности описываются тремя моментами (сдвиг, вытянутость, треугольность), как в ASTRA 7 (`docu/section4.tex`). На первых вызовах (`jcall ≤ 5`) треугольность и давление вводятся постепенно. Если решатель не сошёлся (`jexit ≠ 0`) при `IPART = 1`, выполнение прерывается с `ERROR STOP 'Equilibrium problem at the initial iterations'`. Пример модели — `repo_user_area/equ/flux_emeq`.

В заголовочном комментарии `A2EMEQ` написано, что она вызывается при `IPEQL == 3`. Это неверно: в `SELECT CASE` она стоит в ветке `CASE(1)`.

При `IPEQL < 3` после расчёта метрики структура `equil_now` (IMAS-подобный `type_equilibrium`) заполняется из 3-моментной параметризации (`metrics.f90` стр. 221–252). Поэтому графика и EQDSK-вывод работают и в этих режимах.

### 3.3. ESC

В ASTRA 7 существовал решатель ESC (`docu/section4.tex`: при старой схеме `NEQUIL > 41` включался ESC, ограничение \(N_B \le 121\)). **В исходниках ASTRA 8 ESC нет.** Остались только упоминания в комментариях `BNDRY` (`metrics.f90`), описание `MEQUIL` («Poloidal M (for ESC)») в `astra_variables.json` и запись `'ESC': 2` в `pyparse/equ_parser.py` (около строки 170).

### 3.4. Внешняя метрика (IPEQL = −1, −6, 6)

- **−1**: метрика задаётся в exp-файле X-массивами. `set_external_metric` (стр. 488) по флагам `IFDEFX` выбирает, какие из них заданы, и интерполирует их на транспортную сетку. `ROC3A` проверяет геометрию и при \(R + \Delta < a\) останавливается с `STOP ">>> Error >>> ROC3A >>> Illegal input: R+Delta < a"`. По `addendum_A8.tex`, режимы −1/−6 обходятся, если включён `flightsim`.
- **−6 и 6**: `extmetric_input` (стр. 665) читает файл `input_metric.dat` форматом `'(5555E25.11)'`: подряд `shif, elon, tria, g33, ipol, vr, slat, g11, g22, droda, shiv, squarn`. Это один временной срез без стеллараторных `SG11..SG22`. При этом пользовательская подпрограмма `repo_user_area/sbr/stelmetr.f90` пишет файл `vmec_io/input_metric.dat` в другом формате: сначала число срезов, затем время и расширенный набор, включая `ametr, volum, vrs, rho, sg11..sg22`. В начале она делает `return` при `IPEQL == 6`. Форматы читателя и писателя не совпадают; какой из них актуален, не проверено.

## 4. Схема связи транспорта с 2D-решателем

При IPEQL = 4/5 цепочка вызовов такая:

```text
METRIC (CASE 4:5)
 └─ RHSEQ2                     p', FF', CUTOR из транспортных профилей
 └─ A2GSSOLVER(equil_solver)   metrics.f90:1099
     ├─ BNDRY                  граница (exp / аналитика / внешняя), metrics.f90:1319
     ├─ [IFBEY>0 и не plasma_up]  feqis_main(..., k_fixfree=1, ifplasma=0)   вакуум+цепи
     └─ GSSOLVER               gs_solver.F90: ψ-solver, итерации по объёму и Φ_b
         └─ A_EQUIL
             ├─ feqis_main(..., ifplasma=1)    equil_solver = 101
             └─ spider_run(...)                equil_solver = 3, только #ifdef SPIDER
```

### 4.1. A2GSSOLVER (`src/astra/metrics.f90`, 1099–1316)

- Ток плазмы: `iplnew` вычисляется из `G22·dFP/dρ` на границе. Если `LEQ(4) <= 0` (уравнение для тока не решается), используется `IPL` из модели. При `ITFBP ≠ 0` значение копируется в `IPLFBE` (стр. 1163).
- Давление включает тепловую часть, `NB2EQL·(PBLON+PBPER)/2` и `PFAST`.
- Вращение учитывается при `IPROT = ±3, ±4` (передаётся `omega_rot`).
- Флаг режима: `i = 1` — фиксированная граница, `i = 2` — FBE при `IFBEY >= 1`; при `IPART == 1` всегда `i = 1` (стр. 1209–1211).
- При `IFBEY > 0` и `.not. plasma_up` (фаза пробоя, плазмы ещё нет) вызывается только `feqis_main` с `ifplasma = 0`, то есть считаются вакуумные поля и цепи (стр. 1213–1220).
- Граничные `ABC`, `ELONG`, `TRIAN`, `SHIFT`, `UPDWN` перезаписываются из рассчитанного равновесия, только если граница задана из эксперимента (`raw_boundary%nt > 0`), уже включена FBE (`TIME >= ITFBE`) или используется внешняя граница `use_ext_bnd` (стр. 1268).
- `PSPLEX` и `PSIEXT` берутся из `equil_out`; для IPEQL = 5 `PSPLEX` дополнительно перемасштабируется.

### 4.2. GSSOLVER (`src/astra/gs_solver.F90`)

При первом вызове (`ifbey == 0`) читается namelist `&equil_settings` из `nml_file` (стр. 96–130). Основные параметры и значения по умолчанию (стр. 97–121):

| Параметр | По умолч. | Смысл |
|---|---|---|
| `time_fix_eqpff`, `fix_eqpf_eqff` | 0, 0 | фиксация \(p'\), \(FF'\) после заданного времени; `-1` — брать пользовательские `EQPF`/`EQFF` |
| `cheb_degree` | 5 | степень чебышёвской аппроксимации профилей |
| `iter_one_only_fbe` | — | одна итерация при FBE (±1, см. стр. 571–590) |
| `advanced_methods`, `i3method` | 3, 3 | выбор схемы внутренней итерации |
| `urelax`, `urelax2`, `murelax2` | 0.5, 0.1, 0.2 | коэффициенты нижней релаксации |
| `ydiff`, `ydiff2` | 1e2, 1 | регуляризация ОДУ для \(y = H^2/2\) |
| `max_iter`, `miter_ext` | 10000, 1 | лимиты внутренних и внешних итераций |
| `interp_routine`, `interp_method_rect` | 2, 4 | интерполяция между сетками |
| `epsf_tol`, `epss_tol`, `epsv_tol`, `epsg_tol` | 1e-9, 1e-5, 1e-5, 1e-8 | допуски сходимости |
| `key_no_startz`, `key_no_refits` | — | служебные ключи; при `key_no_refits = 1` читается `exp/equ/tcurrs.wr` (стр. 815–826) |
| `spidat_yes`, `diagnostic_gsef`, `do_adcmp` | — | диагностика и вывод |

Дальше:

- граница перепараметризуется через `surf2surf` (`src/astra/scrunch2d.f90`: фурье-аппроксимация `scrunch` + `mom2rz`; в лог выводится `surf2surf time`);
- прямоугольная сетка берётся из конфигурации машины (`nR`, `nZ`, `Rmin..Zmax` в JSON). Если конфигурации нет, используется 65×65 по габаритам границы ±0.05 м;
- `A_EQUIL` (стр. ~715–860) вызывает решатель; результаты интерполируются обратно на сетку ASTRA.

**Ловушка с namelist.** Если `nml_file` существует, `GSSOLVER` читает из него `&equil_settings`, а `A_EQUIL` — `&spider` (стр. 751–756), причём **вне** `#ifdef SPIDER` и без `iostat`. Значит, при IPEQL = 4/5 файл `exp/nml/<exp>` (или `exp/nml/<machine>`) должен содержать обе группы, даже если SPIDER не используется. Иначе чтение предположительно аварийно завершится (gfortran выдаёт ошибку конца файла). Если файла нет совсем, используются значения по умолчанию. Как выбирается `nml_file`: `src/astra/read_input.f90` стр. 145–150 — `exp/nml/<exp_file>`, иначе `exp/nml/<machine>`.

## 5. FEQIS: устройство решателя

FEQIS (Free-boundary EQuilibrium Solver) — открытый решатель Грэда–Шафранова, входящий в ASTRA 8. Он умеет:

- фиксированную границу (PBE, prescribed boundary) на полярной сетке;
- свободную границу (FBE) на прямоугольной сетке с катушками, пассивными проводниками и лимитером;
- уравнения цепей (эволюция токов в катушках и камере);
- «рефит» токов катушек под заданную форму.

### 5.2. Фиксированная граница (PBE)

При `k_fixfree = 0` (инициализация, `iter_step == 1`, или FBE ещё не включена) FEQIS решает задачу на полярной сетке (ρ, θ), натянутой на заданную границу. Используются `PHI_EQ_2d_PBE.f90`, `jacobians.f90` и `solver_inversion_matrix_gsef.f90`. Ось находится аппроксимацией (`dgels`); при неудаче выдаётся `Error x0, y0 too large`. На выходе — поверхности, \(q\), метрика. Это основной режим для расчётов с экспериментальной границей (пример `flux_feqis`).

### 5.3. Свободная граница (FBE)

При `k_fixfree = 1` (`fbe_core.f90`, `feqis_solvers.f90`):

1. **Внешний поток** `psi_external_calc`: сумма вкладов токов катушек и пассивных проводников через матрицы Грина `greeni` из машинного JSON.
2. **Поток плазмы** `solve_gs2d`: DST по z и трёхдиагональная прогонка по R на однородной сетке `Rrect × Zrect`. Граничные значения на краю расчётной области получаются интегралом Грина (`greenBnd`) — классическая двухпроходная схема (предположительно, по типу фон Хагенова; в комментариях источник не указан).
3. **Ось** `find_new_axis`: метод Ньютона по ∇ψ = 0 (до `n_of_newton_iterations` итераций). Аварийные остановки: `rax is nan in fbe find axis` и `rax is out of boundaries in fbe find axis`, если \(R_{ax} < 0.1\) м или \(R_{ax} > 100\) м (`fbe_core.f90` стр. 396–401).
4. **Граница** `find_psi_boundary`: ищутся X-точки и касание лимитера (`Rlim`/`Zlim`, учитываются при `use_limiter = 1`), а также ограничивающий ящик `zLimPotential`. Параметр `alpsep` (в AUG — 0.995) масштабирует ψ сепаратрисы, чтобы граница не попадала точно на X-точку.
5. **Ток** `new_jrz`: от оси наружу по четырём квадрантам заполняется \(j(R, z)\) по \(p'(\psi_n)\), \(FF'(\psi_n)\) (сетка профилей `nrho2d = 251`), после чего ток нормируется на `iplasma`. Если обход превысил число узлов сетки, выдаётся **`Error in find new boundary (totpoints > nz2*nr2)`** и `stop` (`fbe_core.f90` стр. 705). При NaN-токе — `Total current is nan in fbe current rescaling`.
6. Итерации 2–5 повторяются до сходимости; лимит 10000 даёт `total iterations passed, stopping!` (стр. ~925–932).

### 5.4. Управляющие переменные FEQIS (`transport2fbe`)

После транспортного шага при `IFBEY >= 1` и `ICIRCQ > 0` в `stepup.F90` (стр. 226–227) вызывается `FEQISUPDATE` (IPEQL = 5) или `SPIDUPDATE` (IPEQL = 4). `FEQISUPDATE` переносит рассчитанные токи в `CCOIL = 1e3 · curconduc`, то есть обратно в кА.

## 7. Граница плазмы

`BNDRY` (`metrics.f90` стр. 1319–1484) выбирает источник границы по приоритету:

1. **Экспериментальная граница** из exp-файла:
   - `NAMEXP BNDX` (или `BND`) — точки (r, z), чередующиеся, `NTIMES`/`POINTS`, до `nbnd_max = 400000` чисел;
   - `NAMEXP BNDU <dir>/<file>` — U-файлы `udb/<name>_r` и `_z` (`read_input.f90` около стр. 745–833; пример — `AUG33040_2500`, где используется `33040_2500/33040.bnd.txt`).

   При `nt = 1` граница статична, иначе интерполируется по времени. Если точек ≤ 12, они переупорядочиваются: верх, низ, внутренняя и внешняя.
2. **Внешняя граница** `ext_bnd_in` при `use_ext_bnd` (переменная модуля `metrics`).
3. **Аналитическая**: 8 точек (или `n_bnd`) из `RTOR`, `SHIFT`, `ABC`, `ELONG`, `TRIAN`, `UPDWN`.

Проверка согласованности: `SETVAR` в `src/astra/status.f90` (стр. 422) выдаёт `Inconsistent boundary setting`, если `ABC + |SHIFT| > AB`.

**Вычисленная граница.** При FBE граница находится в `find_psi_boundary` (X-точка или лимитер). Граничные параметры ASTRA (`ABC`, `ELONG`, …) обновляются из результата (см. 4.1). После выключения FBE форма фиксируется, если `fix_shape_after_fbe_off = 1`.

**Связь с данными Глобус-М2.** Для PBE достаточно контура сепаратрисы, например из EFIT-реконструкции, по времени. Его можно положить в U-файлы `_r`/`_z` или блоком `BND` (формат exp-файлов — [04-experiment-data.md](04-experiment-data.md)).

## 8. Свободная граница во времени

Логика в `src/astra/stepup.F90` (стр. 49–227) и `docu/coupling_with_2d_equil_add_EF.tex`:

| Переменная | Значения и действие |
|---|---|
| `ITFBE` | `< 0` — `IFBEY = 0` всегда (FBE выключена); `> 0` — до `TIME < ITFBE` `IFBEY = 0`, далее `IFBEY` увеличивается на каждом шаге. Во время инициализации `astra_main.F90` (стр. 104) принудительно ставит `IFBEY = 0`. **По умолчанию в коде `1.e6`** (FBE фактически никогда не включается), а в документации указано −1 |
| `ITFBP` | `0` — `IBCPSI = 0`, обычное граничное условие по току; `< 0` при `IFBEY >= 1` — граничное условие на ψ: \(\psi_b + [G\,\partial\psi/\partial\rho] = \psi_{ext}\), то есть `PSIFB = PSIEXT − PSPLEX·ROC·dFP/dρ` (стр. 87–95, 191–200) |
| `ICIRCQ` | `0` — без уравнений цепей (`no_circuit_eq = 1`, статическая FBE); `> 0` — цепи решаются, после шага вызывается `FEQISUPDATE`/`SPIDUPDATE` |
| `IPCTRL` | в `A_EQUIL` (`gs_solver.F90` стр. 773–779): `1, −4, −5` → `key_start = 1` (контроллер/рефит), `−3..0` → `key_start = 0`. `key_start` передаётся только в параметры SPIDER (`#ifdef SPIDER`) и используется для `key_no_startz`/`tcurrs.wr`. **В вызов `feqis_main` он не попадает**, так что для FEQIS `IPCTRL` практически не действует (по коду) |
| `SGNIP`, `SGNBT` | знаки \(I_p\) и \(B_t\); в `equ/fbe` — `SGNBT = −1` |
| `RBDOT`, `BBDOT` | адиабатические производные; обнуляются при `IFBEY == 1` (`stepup.F90` стр. 129) |

Порядок на шаге с FBE: `METRIC` внутри `tr_eq_loop` → при `IFBEY >= 1` FEQIS со свободной границей → обновление граничного условия ψ → после шага `FEQISUPDATE` (если `ICIRCQ > 0`).

## 10. Рекомендации по настройке FEQIS для Глобус-М2

Ниже — рекомендуемый порядок работ. Запуском на данных Глобус-М2 он не проверен: это выводы из кода. Ориентировочные параметры машины (\(R_0 \approx 0.36\) м, \(a \approx 0.24\) м, аспектное отношение ≈ 1.5, \(B_t\) до ~1 Т, \(I_p\) до ~0.5 МА) сверьте с `docs/science/shot-and-machine-overview.md` проекта tokomak.

### Шаг 1. Начать с фиксированной границы (PBE)

- Модель: копия `equ/flux_feqis` с `IPEQL = 5`, `NEQUIL = 91` (или 61), `MEQUIL = 90`, `ITFBE = −1` (явно выключить FBE: значение по умолчанию `1e6` работает так же, но −1 нагляднее).
- Exp-файл: `RTOR`, `AB` (радиус камеры), `IPL`, `BTOR`, профили, а также граница из EFIT по времени (`BNDU` или `BND`, раздел 7). Следить, чтобы `ABC + |SHIFT| ≤ AB`.
- Namelist `exp/nml/<exp>` либо не создавать вовсе, либо создать с группами `&equil_settings` и `&spider` (раздел 4.2).
- Критерии проверки: \(q_{95}\), \(\beta_p\), \(l_i\), объём и площадь сечения сравнить с EFIT. Метрика PBE для сильно вытянутой плазмы с низким аспектным отношением должна совпадать с EFIT; если нет — увеличить `MEQUIL`, проверить точность `surf2surf` (число мод фурье-аппроксимации границы).

### Шаг 2. Описание машины `exp/cnf/<mach>_description_in.json`

- Имя из 4 символов, например `glm2` (запуск с `-dev glm2`).
- Сетка: равномерная, \(R_{min} > 0\). При аспектном отношении ≈ 1.5 плазма подходит близко к центральному столбу; внутренний край сетки должен оставаться правее центрального соленоида и столба, но захватывать внутреннюю стенку. Ориентир: R от ~0.1 до ~0.75 м, Z примерно ±0.7 м, 65×65 или 129×129. Ограничение кода `rax < 0.1 → stop` для Глобус-М2 (\(R_{ax} \approx 0.4\) м) не мешает, но запас всего в несколько раз.
- Катушки: центральный соленоид (несколько секций, если они запитываются отдельно), катушки полоидального поля, катушки управления вертикальным/горизонтальным положением. Указать `m_turns`, `m_equiv` (общий источник питания — одна цепь), `n_elem_coil`, матрицу `resConduc`.
- Камера: на Глобус-М2 камера близко к плазме и вихревые токи в ней значимы. Её нужно описать сегментами `x1..x4` с удельным сопротивлением `res_blan` и толщиной `width_blan`.
- Лимитер `Rlim`/`Zlim` — реальный контур первой стенки; в первую очередь важна внутренняя (центральная) стенка.
- После запуска `as_exe.py` проверить, что `_full.json` создан и в логе `green` выведены разумные `nactive, ncoils, nconduc`.

### Шаг 3. Проверка вакуума и статической FBE

- Сначала `ICIRCQ = 0` (статическая FBE), `ITFBE` = момент плато тока, а `CCOILX` — измеренные токи на этот момент. Сравнить рассчитанную сепаратрису с EFIT. Расхождение здесь указывает на ошибки в геометрии и витках катушек или на знаки (`SGNIP`/`SGNBT` и знак токов в катушках).
- Режим `refit_mode = 818` с изопотоковыми точками позволяет восстановить токи по известной границе и проверить описание катушек. Переменные придётся задать пользовательской подпрограммой с `use transport2fbe` (раздел 5.4).

### Шаг 4. Динамика с цепями

- `ICIRCQ = 1`, `VCOILX` — напряжения источников. Шаг `TAU` должен быть малым относительно постоянной времени камеры (в примере AUG 2 мс; для Глобус-М2, предположительно, нужен меньший шаг).
- Сферический токамак сильно вытянут и вертикально неустойчив: без активной стабилизации FBE с цепями даст VDE и в итоге `Error in find new boundary`. Для оценки есть `estimate_tau_VDE` в `circuit.f90`; режимы `refit_mode = 1` и `3` стабилизируют ось и форму.

### Чего избегать

- Не включать SPIDER (`IPEQL = 4`): в открытой сборке его нет.
- Не полагаться на `FEQIS_manual.tex`: описанный там формат `exp/equ/<machine>/coil.dat` и др. устарел (раздел 14).

## 12. VMEC и стеллараторный режим

### 12.1. Физика: обобщённая диффузия тока

`docu/astell_manual.tex` (F. Solfronk) описывает обобщение уравнения диффузии тока на 3D через матрицу восприимчивостей \(S_{ij}\) (по Strand–Houlberg 2001). Продольный ток выражается через \(W(F, I)/(V' B_0)\), \(\rho_B = G_{vac}/B_0 \cdot S_{11}/\det S\), а в коде используются массивы `SG11`, `SG12`, `SG21`, `SG22`, `GVAC`. Эти массивы задействованы в стеллараторных ветках `CUOFMU`, `CUOFP`, `FPMUOFCU` (`metrics.f90`, IPEQL 6/7/9). В тексте сказано, что связанного стеллараторного решателя нет; это устарело, теперь он есть — VMEC через IPEQL = 7.

### 12.2. VMEC (IPEQL = 7)

Код — `src/astra/a2vmec.f90` (529 строк), `src/astra/vmec_indata.f90`, `src/astra/stella_module.f90`; DKES — `src/astra/a2dkes.f90`.

- `vmec_interface` читает namelist `&vmec` из `nml_file`: `phi_full_surfaces`, `dt_boozer`, `vac_phase_stel` (0 — реальный вакуум на старте для стелларатора, 1 — для токамака), `mboz`, `nboz`, `f_vmec_settings`. Пример — `repo_user_area/exp/nml/steltest`.
- Переменные окружения: `MPI_COMMAND`, `N_NODES` (задаётся `exe/Build` из ключа `-nodes`), `PYTHON_BIN`, `STELLOPT_HOME` (`exe/astra_rc`: по умолчанию `${ASTRA_EXT}/STELLOPT/`; примеры в `platform/env.tok`, `platform/env.w7x`).
- Файл `f_vmec_settings` (шаблон `vmec/templates/stell_files.nml`) задаёт группу `&vmec_to_astra_inputs` (`wout_VMECoutput.nc`, `boozmn_VMECoutput.nc`, `vmecinput.dat`, `vmec2astra.bin`, `vmecinput_template.dat`, `inboozer.dat`, `true_surf.txt`, каталоги `vmec`, `templates`, `dat`) и группу `&ASTRA_DKES_INTERFACE`.
- `astra2vmec` формирует входной файл VMEC из шаблона `vmec/templates/vmecinput_template.dat` (NFP = 3, конфигурация типа W7-AS, `LFREEB = F`). Подставляются профили давления и тока (сплайны `AM/AI/AC_AUX`, не более 100 узлов), `CURTOR`, `PHIEDGE`, `NS` из `NEQUIL`, ось. Затем запускается `$MPI_COMMAND -n $N_NODES $STELLOPT_HOME/VMEC2000/Release/xvmec2000` (повторные вызовы — с `reset=`) и `xbooz_xform`.
- Python-скрипты `vmec/python/extract_boozer_data.py` и `vmec2bin.py` пишут бинарный файл, который `VMECbin2astra` читает в ASTRA: `ROC`, `RTOR`, `ABC`, `BTOR`, `GVAC`, `SG11..SG22`, `MV`, `VR`, фурье-гармоники `rmnc/zmns` и др. `IPOL` вычисляется из `S21`, `S22` (в комментарии — ссылка на Solfronk, PPCF 2026).
- На первом шаге при `vmec_vacuum > 0` метрика строится через `EQCYL_STELLA` + `RHSEQ`, затем вызывается VMEC (`metrics.f90` стр. 193–199).

Таблица `vmec_option` (`metrics.f90` стр. 54–107):

| vmec_option | vmec_vacuum | vmec_tau | vmec_dteq | yes_boozer |
|---|---|---|---|---|
| 0 | 1 | 1 | 1 | 1 |
| 1 | 2 | 1 | 1 | 1 |
| 2 | 2 | 2 | 1 | 1 |
| 3 | 2 | 2 | 0 | 1 |
| 4 | 1 | 1 | 1 | 0 |
| 5 | 2 | 1 | 1 | 0 |
| 6 | 2 | 2 | 1 | 0 |
| 7, 9 | 2 | 2 | 0 | 0 |
| 8 | 2 | 2 | 0 | 1 |

Смысл флагов по ветке `CASE(7)`:

- `vmec_vacuum > 0` — вакуумный старт;
- `vmec_tau = 1` — на первых двух шагах вызывать VMEC; `vmec_tau = 2` — только `vmec2astra.py`, без VMEC;
- `vmec_dteq` — вызывать ли VMEC при плановом пересчёте раз в `DTEQL` (0 — только конвертер);
- `yes_boozer` — запускать ли BOOZ_XFORM.

Модели: `equ/transpstell` (`vmec_option = 0`, `NEQUIL = 99`, `MEQUIL = 51`), `equ/transpstell2` (`vmec_option = 9`, транспорт из DKES через `dkes2astra_variables`), `equ/tok2vmec` (`vmec_option = 4`, токамак через VMEC; вызывает `TOKSTELOUT`, но подпрограммы с таким именем в `repo_user_area/sbr` нет). Модель `equ/stelxes` содержит `IPEQL = 4` (SPIDER) — вероятно, это не стеллараторная модель в смысле VMEC; не проверено.

Запуск по `memo_stella`:

```bash
exe/as_exe -m transpstell -v steltest -s 0. -e 4. -tpause 0. -nodes 8
```

Требуется собранный STELLOPT с подкаталогами `VMEC2000`, `BOOZ_XFORM`, `DKES` (`memo_stella`). Для токамаков Глобус-М2 этот путь не нужен.

## 13. Типичные ошибки и диагностика

| Сообщение | Где | Вероятная причина и что делать |
|---|---|---|
| `Error in find new boundary (totpoints > nz2*nr2)` | `src/feqis/fbe_core.f90:705`, `new_jrz` | при заполнении тока от оси обход превысил число узлов: область \(\psi_n < 1\) не замкнута внутри сетки (плазма касается края, потеряна X-точка или лимитер, VDE, ось ушла). Увеличить расчётную область, проверить лимитер и `use_limiter`, уменьшить `TAU`, проверить токи и знаки катушек. В примере `fbe`/`AUG33040_2500` возникает на t = 2.62 и в эталоне |
| `rax is out of boundaries in fbe find axis` / `rax is nan …` | `fbe_core.f90:396–401` | ось не найдена или \(R_{ax} \notin [0.1, 100]\) м; плохое начальное приближение или неправильная сетка |
| `Total current is nan in fbe current rescaling` | `fbe_core.f90` (~стр. 800) | NaN в \(p'\)/\(FF'\) или пустая плазменная область |
| `total iterations passed, stopping!` | `fbe_core.f90` (~стр. 930) | статические итерации FBE не сошлись за 10000 шагов |
| `Error x0, y0 too large` | `src/feqis/PHI_EQ_2d_PBE.f90` | PBE: аппроксимация оси разошлась; граница слишком грубая или вырожденная |
| `Equilibrium problem at the initial iterations` | `metrics.f90`, `A2EMEQ` | EMEQ не сошёлся на старте (IPEQL = 1) |
| `>>> Error >>> ROC3A >>> Illegal input: R+Delta < a` | `metrics.f90`, `ROC3A` | несогласованная внешняя метрика или геометрия (IPEQL = −1) |
| `Inconsistent boundary setting` | `src/astra/status.f90:422` | `ABC + |SHIFT| > AB` |
| ошибка конца файла при чтении namelist | `gs_solver.F90` стр. 127, 754 | в `exp/nml/<exp>` нет группы `&equil_settings` или `&spider` (раздел 4.2) |
| `"Rmin" not found, skipping Green-function calculation` | `exe/greenMatrices.py` | предупреждение, не ошибка: для машины нет описания катушек (`iter`, `jet`); FBE для неё невозможна |
| остановка при `j_iter > 150` | `src/feqis/circuit.f90` | итерации рефита не сошлись |

Общие советы:

- Смотреть, что FEQIS пишет в `dat/` (`output_timefit.dat`, `file_fit_currents_output_*`).
- Включить диагностику `diagnostic_gsef`/`spidat_yes` в `&equil_settings` (точный эффект не проверен).
- Сравнить с PBE-расчётом на той же границе.
