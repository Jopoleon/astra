## 1. Система единиц

ASTRA использует смешанную «практическую» систему (`docu/section4.tex`, таблица 4.1):

| Величина | Единица | Комментарий |
|---|---|---|
| длина | м | `RTOR`, `AB`, `RHO`, `AMETR` |
| площадь | м² | `SLAT`, `AREAT`, `VR`, `G11` (м²) |
| объём | м³ | `VOLUM`, `VOLUME` |
| время | с | `TIME`, `TAU` |
| скорость | м/с | `CN`, `VTOR`, `UPAR` |
| коэффициент переноса | м²/с | `DN`, `HE`, `XI`, `DFj` |
| плотность | 10¹⁹ м⁻³ | `NE`, `NI`, `NIZ1` |
| источник частиц | 10¹⁹ м⁻³ с⁻¹ | `SN`, `SNEBM` |
| поток частиц через поверхность | 10¹⁹ с⁻¹ | `QN` |
| плотность потока частиц | 10¹⁹ м⁻² с⁻¹ | `GN`, `GNX` |
| температура | кэВ | `TE`, `TI`, `TN` |
| частота/обратное время | с⁻¹ | `SNN`, `QFFjB` |
| мощность | МВт | `QE`, `QI`, `QNBI`, `QECR` |
| плотность мощности | МВт/м³ | `PE`, `POH`, `PRAD` |
| плотность потока мощности | МВт/м² | — |
| энергия | МДж | `QETB·TEB` в МДж/кэВ·кэВ |
| магнитное поле | Т | `BTOR`, `BMAXT` |
| магнитный поток | В·с (= Вб) | `FP`, `FTO` |
| напряжение | В | `UPL`, `ULON`, `UEXT` |
| ток | МА | `IPL`, `IPLFBE` |
| плотность тока | МА/м² | `CU`, `CD`, `CUBS` |
| индуктивность | мкГн | `LEXT` (в JSON записано `mkH`) |
| проводимость | МС/м | `CC` (в JSON записано `MA/(V*m)` — то же самое) |
| частота волн | ГГц | `FECR`, `FLH`, `FICR`, `FFW` |

Числовые множители, которые часто встречаются в коде:

- `625 = 1/1.6e-3` — переход между кэВ·10¹⁹ м⁻³ и МДж/м³ (`docu/section4.tex`, уравнение `Amain`);
- `0.0016` — обратный множитель (например `QU = ... *0.0016`, `pyparse/const_text.py::UPEQN`);
- `mu0 = 0.4·π` — магнитная постоянная в единицах МА, м, мкГн (`src/misc/pi_const.f90`);
  `muvac = 4e-7·π` — в СИ;
- `GP = 3.14159265359`, `GP2 = 2·GP`, `GP2_sq = GP2²` (`src/misc/pi_const.f90`);
- `5.9773e+07` — множитель `TTRQ = 5.9773e7·RTOR·SCUBM` (оценка из описания `TTRQ` в JSON, автор пишет «I guess»).

## `astra_variables.json`

### Назначение

Реестр **всех** именованных переменных ядра. Он одновременно:

1. задаёт **порядок**, а значит индексы переменных в плоских массивах
   (`varValues`, `profiles(:, k)` …, см. [05-solver-core.md §3](05-solver-core.md#3-хранение-переменных-плоские-массивы-и-указатели));
2. даёт имена ключей при записи/чтении выходных JSON (`src/astra/json_rw.f90`);
3. служит словарём для парсера модели и эксп. файлов
   (`pyparse/equ_parser.py`, `pyparse/exp_parser.py`, `pyparse/code_gen.py`).

Ядро читает его в `json_vars::read_metadata` (`src/astra/json_vars.f90:48`) из **текущего
каталога** при старте. Имена ограничены 6 символами (`character(len=6)`).

**Добавление переменной** = добавление ключа в нужную группу. Поскольку индексы
позиционные, вставка в середину сдвигает все последующие индексы; сгенерированный
`associate_pointers.f90` при этом должен быть перегенерирован (пересборка модели).
Старые выходные JSON читаются по именам ключей (`read_ajson`), *предположительно*
совместимость сохраняется, но специально не проверялось.

### Структура

```json
{
  "variables":  { "AB": {"units": "m", "desc": "Limiter position in the mid"}, ... },
  "variables_x": { ... },
  "constants":  { "CF1": {...}, ... },
  "control":    { "DPOUT": {"units": "s", "desc": "Profiles/time output interval"}, ... },
  "internInt":  { ... },
  "internDbl":  { ... },
  "profiles":   { "AIMPT": {...}, ... },
  "profiles_x": { "CAR1X": {...}, ... },
  "strahl":     { ... },
  "equil_signals":  { ... },
  "equil_profiles": { ... },
  "equil_rect": { ... },
  "equil_rz2d": { ... },
  "equil_coord": { "gradvcell": {"unit": "m^2", "desc": "..."}, ... }
}
```

| Группа | Записей | Массив в ядре | Тип |
|---|---:|---|---|
| `variables` | 135 | `scalars::varValues` | скаляры модели |
| `variables_x` | 135 | `scalars::varxValues` | те же, из эксп. файла |
| `constants` | 162 | `scalars::constValues` | C-параметры (по умолчанию 1) |
| `control` | 15 | `scalars::controlValues` | управление счётом (+`DTEQ` в хвосте) |
| `internInt` | 33 | `scalars::internIntValues` | целые флаги и размеры |
| `internDbl` | 46 | `scalars::internDblValues` | внутренние вещественные |
| `profiles` | 454 | `status::profiles(NRD, :)` | радиальные профили |
| `profiles_x` | 106 | `status::profiles_x(NRD, :)` | эксп. профили |
| `strahl` | 13 | — | обмен со STRAHL |
| `equil_signals` | 8 | `equil_now%global_param` | скаляры равновесия |
| `equil_profiles` | 28 | `equil_now%profiles_1d` | 1D-профили равновесия |
| `equil_rect` | 4 | `equil_now%eqgeometry%rectgrid` | ψ(R,Z) на прямоугольной сетке |
| `equil_rz2d` | 5 | `equil_now%coord_sys%position` | контуры поверхностей |
| `equil_coord` | 6 | `equil_now%coord_sys` | величины в ячейках |

Особенности:

- в `equil_coord` ключ единиц — `"unit"`, а не `"units"` (опечатка; читателям JSON это надо учитывать);
- во многих профилях `desc` обрезан на первой точке или запятой (`"Limiter position in the mid"`,
  `"<(B0/B)^2*(1."`) — *предположительно*, артефакт автоматической конвертации из старых таблиц;
- у `TTRQ`/`TTRQI` единицы и описание склеены в поле `units` (ошибка в JSON);
- у `CAR1..128`, `F0..F9`, `GFj`, `SFj` и т.п. описания пустые.

## 3. Скаляры: `variables` и `variables_x`

`variables_x` повторяет `variables` с суффиксом `X` — это значения, прочитанные из
`exp/<exp>` и интерполированные на `TIME` (`set_x_data::set_x_scalars`). Какое значение
реально используется, решает модель (например `IPL = IPLX` в `detvar.f90`) и флаг
`IFDFVX` (0 — данные, постоянные; 1 — данные, зависят от времени; 2 — из модели;
3 — с клавиатуры; 4 — запрещено менять).

### 3.1. Геометрия и поле

| Имя | Ед. | Смысл |
|---|---|---|
| `RTOR` | м | большой радиус (центр камеры); `IFDFVX=4` |
| `BTOR` | Т | тороидальное поле на `RTOR` |
| `AB` | м | положение лимитера в экваториальной плоскости (малый радиус) |
| `ABC` | м | граница расчёта (малый радиус); должно быть `ABC ≤ AB` |
| `AWALL` | м | положение стенки по горизонтали |
| `ELONG`, `TRIAN` | — | вытянутость и треугольность граничной поверхности |
| `ELONM`, `TRICH` | — | вытянутость и треугольность камеры |
| `SHIFT` | м | сдвиг граничной поверхности |
| `UPDWN` | м | вертикальный центр LCFS `0.5·(Ztop+Zbot)` |
| `GVAC` | Т·м | `<R B_φ>` на оси в вакууме; `RTOR·BTOR` в токамаке |
| `PHIEDG` | Т·м² | вакуумный тороидальный поток на краю (стелларатор); по умолчанию +∞ = «не задано» |

### 3.2. Плазма и ток

| Имя | Ед. | Смысл |
|---|---|---|
| `IPL` | МА | ток плазмы |
| `UEXT` | В | внешнее напряжение (граничное условие для `FP`) |
| `LEXT` | мкГн | внешняя индуктивность (уравнение цепи) |
| `AMJ`, `ZMJ` | — | масса (в mₚ) и заряд основных ионов |
| `AIM1..3` | — | массы примесей 1..3 (в mₚ) |
| `GN2E`, `GN2I` | — | множители конвективного потока тепла `5/2·γ` (по умолчанию 0) |
| `WNE`, `WTE`, `WTI` | м | ширина экспоненциального спада `NE`, `TE`, `TI` за `NA1` (SOL) |

### 3.3. Нейтралы и нагрев

| Имя | Ед. | Смысл |
|---|---|---|
| `NNCL`, `ENCL` | 10¹⁹ м⁻³, кэВ | плотность и энергия холодных нейтралов на краю |
| `NNWM`, `ENWM` | 10¹⁹ м⁻³, кэВ | то же для тёплых нейтралов |
| `QNBI` | МВт | полная мощность пучков |
| `QECR`, `FECR` | МВт, ГГц | ЭЦ-нагрев: мощность, частота |
| `QICR`, `FICR` | МВт, ГГц | ИЦ-нагрев |
| `QLH`, `FLH` | МВт, ГГц | нижнегибридный нагрев/ток |
| `QFW`, `FFW` | МВт, ГГц | быстрая волна |

### 3.4. Свободные скаляры

| Имя | Смысл |
|---|---|
| `ZRD1..ZRD96` | свободные скаляры из эксп. файла (`ZRDjX`) для использования в модели; описаний нет (`docu/section4.tex:1373–1393`) |

## 8. Радиальные профили: `profiles`

454 профиля, все длины `NRD = 801`, значимы узлы `1..NA1` (часть — до `NB1`).
Ниже сгруппированы по смыслу; пустые описания JSON восстановлены по коду/докам.

### 8.1. Состояние плазмы

| Имя | Ед. | Смысл |
|---|---|---|
| `NE`, `NEO` | 10¹⁹ м⁻³ | плотность электронов (текущая/предыдущий шаг) |

## 15. Форматы файлов и каталоги

| Имя | Что это |
|---|---|
| `equ/<model>` | модель (исходник) |
| `equ/log/<model>` | лог/значения скаляров модели, читаемые `assign_val` (`parse_utils.f90`) |
| `exp/<exp>` | вариант эксп. данных (скаляры, профили, `BND`, `CCOILX`, `VCOILX`) |
| `exp/nml/<exp>`, `exp/nml/<machine>` | namelist-ы (`equil_settings`, `spider`, `vmec`, …) |
| `exp/cnf/<machine>_description_in.json` | описание машины (сетка R,Z, катушки) |
| `exp/nbi/<...>` | конфигурация NBI (`inquire_fname('nbi')`) |
| `udb/` | U-файлы, на которые ссылается `exp` (`NAME U-FILE:name:factor`) |
| **U-file** | текстовый формат TRANSP/ITER Profile DB: заголовок + 1D/2D массивы по времени и радиусу (`read_input.f90::ufheader`, `ufrd`) |
| `tmp/astra.nml` | namelist `astra_log` от `as_exe.py`: `equ_file`, `exp_file`, `task`, `machine`, `debug`, `tbeg_nml`, `tend_nml`, `restart`, … |
| `tmp/<exp><equ>.ipc` | файл описания IPC для подпроцессов TGLF/QLK/NEO |
| `src/tmp/*.f90` | сгенерированный из модели Fortran |
| `bin/<model>_batch.exe`, `bin/<model>_gui.exe` | исполняемые файлы |
| `ncdf_out/<exp><equ>-<n>.json` | выходные JSON (по одному на момент `DPOUT`) |
| **CDF** / NetCDF | выходной файл, собираемый `json2cdf` в `as_exe.py` из JSON (глава 08) |
| `astra_variables.json` | реестр переменных (см. выше) |
| `docu/*.tex` | исходники руководства ASTRA (частично описывают A6/A7) |
