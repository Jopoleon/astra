## Назначение

Монорепозиторий вокруг транспортного кода **ASTRA 8** (оригинал: <https://gitlab.mpcdf.mpg.de/git/astra.git>, IPP Garching, LGPL v2.1+). Публичный репозиторий: <https://github.com/Jopoleon/astra>.

Цели:

1. **Рабочий установщик ASTRA 8 для обычной Ubuntu / WSL** для лаборатории «Глобус-М2» (ФТИ им. Иоффе): Никита Жильцов и коллеги должны ставить и запускать ASTRA на чистой системе. В перспективе — apt-пакет.
2. **Понять и изучить ASTRA**: устройство, сборка, модели, внешние модули, настройки других площадок.

## Что уже известно (не переоткрывать)

### Как устроена ASTRA 8

- Исполняемый файл **собирается заново под каждую модель**: `exe/as_exe` → `exe/as_exe.py` → `exe/Build` → `get_platform` + `platform/env.<platform>` + `exe/astra_rc` → `make -f exe/Makefile` (Python-парсер `pyparse/` превращает модель `equ/<m>` и эксперимент `exp/<e>` в Fortran) → `make -f exe/Makexpr` (IPC-программы TGLF/QuaLiKiZ/NEO) → `bin/<m>_gui.exe` или `bin/<m>_batch.exe` → `json2cdf` → `ncdf_out/<e><m>.CDF`.
- Пользовательская область (`equ/`, `exp/`, `udb/`, `exe/`, `sbr/`, `fnc/`, ...) копируется из `repo_user_area/` и игнорируется git оригинала.
- Внешние модули ищутся в `$ASTRA_EXT` по раскладке из `exe/astra_rc`. Обязательна только json-fortran (`$ASTRA_EXT/json/9.0.2`).
- Закрытые коды IPP: RABBIT (NBI), TORBEAM (ECRH), SPIDER, STRAHL (404 анонимно, только SSH для аккаунтов IPP). С мая 2026 (`2ec99235`) есть заглушки, но модели с `TORBA`/`RABBIT(...)` нужно комментировать `!`. Открытые, но пока не ставятся: TGLF, NEO (GACODE), QuaLiKiZ, QLKNN (нужен MPI).
- Запуск в A8: `astra8 -m <модель> -v <эксперимент> -s t0 -e t1 [-batch]`; в ASTRA 7 было `astra <эксперимент> <модель>`. Без аргументов `as_exe` повторяет последний расчёт.

### Проблемы на Ubuntu и как установщик их решает

Подробно — `installer/docs/DETAILED.md`, раздел 3. Кратко:

| проблема | решение |
|---|---|
| `core.autocrlf=true` (WSL/Windows) → CRLF → `required file not found` | клон с `core.autocrlf=false`; в наших репо `.gitattributes` с `eol=lf` |
| `get_platform` → `mypc`, а `env.mypc` нет; hostname `node*`/`tok*`/`omega*` подхватывает чужую площадку | `platform/env.ubuntu`, симлинк `env.mypc`, переключатель `ASTRA_PLATFORM` в `get_platform` |
| gfortran обрезает строки на 132 символах (`a2vmec.f90`) | `-ffree-line-length-none` |
| `--as-needed` в Ubuntu + `-lX11` раньше `libgraph.a` → `undefined reference to XOpenDisplay` | `LD_FLAGS=-Wl,--no-as-needed` |
| MKL прописан в Makefile жёстко | OpenBLAS через `MAKEFLAGS="MKL_LIB=-lopenblas"` (по умолчанию) или MKL из wheel `mkl-static` с PyPI |
| многопоточный OpenBLAS внутри OpenMP → переподписка (57 с вместо 30, 21 мин sys) | `OPENBLAS_NUM_THREADS=1` |
| `Makexpr` собирает TGLF/QLK/NEO без библиотек | цели убираются из `exe/Makexpr` |
| тестовая модель `flux_feqis` вызывает TORBEAM/RABBIT | строки комментируются |
| `pyparse/exp_parser.py::parse_u_line` падает на U-строках A7 (табы, комментарии `****`) | патч-регулярка, понимает форматы A7 и A8 |
| `as_exe` всегда возвращает 0 | успех = `>>> ASTRA normal exit >>>` + наличие CDF |

Правки установщика накладываются на **рабочую копию пользователя** (`~/astra/a8`, клон из MPCDF), а не на `astra-src/`. Перенос фиксов в `astra-src/` — отдельное решение.

### Проверенные факты

- Проверенная версия ASTRA: `e66f6ba13dd0160ed5b3dd37a46d0671cb81e85d` (2026-10-01, в окне программы «ASTRA 8.6»). Свежий `main` `6728111` тоже собирается и проходит тест.
- Установщик по умолчанию качает **один коммит** (`git fetch --depth 1`, ~90 МБ); для этого `--ref` должен быть веткой, тегом или **полным** хэшем. Короткий хэш — только с `--full-history`.
- Чистые `ubuntu:24.04` (gfortran 13) и `ubuntu:22.04` (gfortran 11): установка с apt за 2.5–3 мин, тест `flux_feqis`/`aug34954` 30–45 с.
- Сравнение с эталонами `regressions/*.CDF` (Intel + MKL на кластере IPP): встроенный допуск `compareRegressions.py` 1e-7 для gfortran всегда «падает». Реальное расхождение на `fbe`/`AUG33040_2500` — ~0.1 % по `CU`/`MU`, 1–3 % по `psiaxis`; последний шаг (t=2.62) обрывается с `Error in find new boundary` так же, как в эталоне. `flux_feqis` с эталоном не сравним (эталон с RABBIT/TORBEAM).
- OpenBLAS и MKL дают одинаковый результат (до 3e-6); расхождение с эталоном даёт компилятор, а не BLAS.
- `exp/readme` + `equ/showdata` из репозитория не запускаются: ссылаются на отсутствующие `udb/00000.tes`/`00000.tis` и написаны в формате A7 (после патча парсера падает `AssertionError` в `parse_exp2d`).
- Docker-образ `astra8` (~2.2 ГБ) собирается тем же установщиком; сборка включает тестовый расчёт. Окно работает через WSLg.

### «Глобус-М2» (подробно — `docs/research/astra8-for-globus-m2-2026-10-01.md`)

- **NBI:** встроенный модуль Полевого (`src/nbi`) работает в нашей сборке и совпадает с эталоном IPP до 0.5 % (`flux_nbi` без `TORBA`). Учитывает CX, прострел и первую орбиту (`NBORBCO`, ведущий центр). NUBEAM в ASTRA нет ни в A7, ни в A8 — у лаборатории это внешняя связка.
- **Равновесие:** `IPEQL=5` (FEQIS); свободная граница включается `ITFBE>0`, по умолчанию граница заданная. С заданной границей геометрия машины не нужна; синтетическая плазма с `A=1.5`, `κ=1.9` (`~/astra/a8/exp/gm2synth`) считается устойчиво. Для свободной границы нужен `exp/cnf/<машина>_description_in.json` (полный пример только AUG), токи `CCOIL` и подпрограмма `transport2fbe`.
- **Ловушки:** имя машины `-dev` — не длиннее 4 символов и без `_` (`gm2`); без `-dev` берётся сетка AUG; `ABC` по умолчанию 0.3 м — для «Глобуса» задавать явно; каждой модели нужен `equ/log/<модель>`.
- **Перенос из A7:** файлы эксперимента ломает только Python-парсер сборки (`pyparse/exp_parser.py`: неявная сетка `GRIDTYPE<10`, `18/19`, `*`-комментарии, текст в данных обрывает блок молча); фортрановский `read_exp` формат A7 понимает. В моделях `%`-комментарии A7 не работают (только `/* */`), `#`-блоков и `INCLUDE` нет. Конвертера нет.
- **Архив MDSplus:** сейчас там только `I_p`, `B_T` (из `Itf`), линейная плотность, времена NBI2. Томсон, CXRS, `Z_eff`, мощность NBI, EFIT — вне MDSplus (NAS лаборатории).

## Правила работы

### Исходники ASTRA

- Ничего не вычищать из `astra-src/` по своей инициативе: чужие `platform/env.*`, регрессии, модули — материал для изучения. Удалять только по явной просьбе.
- Правки исходников ASTRA — обычные коммиты в `astra-src/` этого репозитория; значимые правки записывать в журнал `docs/local-fork.md`. Ветку `astra-upstream` руками не трогать.
- Обновления из MPCDF — только `tools/sync-upstream.sh`, не голым `git pull`: он притащит неочищенную историю (~1 ГБ, файлы по 215 МБ). Подробно: `docs/local-fork.md`.
- Соблюдать LGPL: не удалять `LICENSE`, копирайты и авторство оригинала; при распространении изменённой ASTRA указывать, что это модифицированная версия и откуда оригинал.
- Не публиковать и не пытаться добывать закрытые коды IPP (RABBIT, TORBEAM, SPIDER, STRAHL).

### Установщик

- После изменения `install_astra8.sh` проверять минимум: `bash -n`, повторный запуск на рабочей установке (`bash installer/install_astra8.sh --no-apt -y`) и чистый контейнер (команды ниже). Для изменений, касающихся старых систем, — ещё `ubuntu:22.04`.
- Установщик должен оставаться идемпотентным: повторный запуск не перезаписывает файлы пользователя в `equ/`, `exp/`, `udb/`.
- Совместимость: Ubuntu 22.04 (coreutils 8.32, gfortran 11) и 24.04. Не использовать то, чего нет в 22.04 (например, `cp --update=none` без проверки).
- Новый проверенный коммит ASTRA менять одновременно в `install_astra8.sh` (`ASTRA_REF`, полный хэш), `installer/docker/Dockerfile` (`ARG ASTRA_REF`) и в документации.
- При изменении поведения обновлять `installer/README.md` (для пользователей, просто и со всеми командами) и `installer/docs/DETAILED.md` (подробно, с причинами).
- Установщик по умолчанию ставит ASTRA в `~/astra` — не клонировать этот репозиторий туда.

### Проверка

```bash
# синтаксис
bash -n installer/install_astra8.sh

# чистая система (то же, что сделает пользователь)
docker run --rm -v "$PWD/installer:/inst:ro" ubuntu:24.04 \
  bash -c 'bash /inst/install_astra8.sh -y; echo EXIT=$?'

# путь из публичного README
docker run --rm ubuntu:24.04 bash -c 'apt-get update -qq && apt-get install -y -qq git ca-certificates \
  && git clone -q https://github.com/Jopoleon/astra.git ~/astra-repo \
  && cd ~/astra-repo/installer && bash install_astra8.sh -y'

# Docker-образ (сборка сама прогоняет тест)
cd installer && docker build -f docker/Dockerfile -t astra8 .
```

Успех — `ok: ASTRA normal exit` и код возврата 0. Код возврата `as_exe` ничего не значит.

### Подводные камни для агентов

- `pkill -f <шаблон>` в той же bash-команде убивает собственную оболочку (шаблон есть в её командной строке). Останавливать процессы через `pgrep` + PID или `docker stop`.
- Скриншот рабочего стола Windows (проверка окна через WSLg) захватывает весь экран пользователя: сразу удалять из `%TEMP%` и не хранить.
- GUI-запуск ASTRA не завершается сам: запускать под `timeout` или останавливать после проверки.
- Зеркала Ubuntu бывают очень медленными (`libmkl-dev` ~1 ГБ качался ~50 КБ/с); большие зависимости лучше брать с PyPI/GitHub.
- `exe/as_exe` возвращает 0 даже при ошибке компиляции — искать `Error` в выводе.

### Общие правила (из проекта tokomak)

- Изучать постепенно и не додумывать: если деталь формата или поведения не ясна, ссылаться на конкретный файл исходников или внешнюю документацию.
- Рабочее дерево может содержать чужие незакоммиченные изменения — не откатывать их без явной просьбы.
- Коммитить и пушить только по просьбе пользователя.
- Репозиторий публичный: не коммитить пароли, ключи, конфиги WireGuard/SSH, внутренние данные лаборатории и личные заметки. Процедуры документировать без секретов.
- Устаревшие инструменты и скрипты не удалять: они нужны как справочный материал.
- У любой «последней» внешней ссылки или версии указывать точную дату.
